### Changed
- **Invalid queries are refused before they run.** A compile-time check now runs after a statement parses and before it is planned, and refuses what openCypher defines as an error, whatever the data. The message opens with the openCypher error kind (`parse: VariableTypeConflict: …`). Queries that were accepted before and are now refused: a name used as two kinds of thing (`MATCH ()-[r]-() MATCH (r)`, `MATCH (r)-[r]-()`, `MATCH r = ()-[]-(), (r)`, `WITH 123 AS n MATCH (n)`: `VariableTypeConflict`; these returned rows or no rows, or failed only when a row reached them); a path name that is already bound (`MATCH (p) MATCH p = ()-[]-()`, `MATCH p = (p)-[]-()`: `VariableAlreadyBound`); `MATCH (a) CREATE (a)`, which created nothing (`VariableAlreadyBound`); an aggregate in `WHERE` (`WHERE count(a) > 10`) or in an `ORDER BY` whose projection does not aggregate (`WITH n.x AS x ORDER BY max(n.y)`: `InvalidAggregation`); an unaliased aggregate in `WITH` (`WITH a, count(*)`: `NoExpressionAlias`); two `WITH` items with one name (`WITH 1 AS a, 2 AS a`, which kept the last: `ColumnNameConflict`); `UNION` mixed with `UNION ALL` (`InvalidClauseComposition`), and `UNION` parts with different column names, now refused before any part runs (`DifferentColumnsInUnion`); a call of an unknown function, now refused even when no row would reach it (`UnknownFunction`); `type()` of a node or path, `length()` of a node or relationship, `size()` of a path, `x IN` a literal that is not a list (`1 IN 123`, which compared the value as one element), a property of a literal number, string, boolean or list (`WITH 123 AS x RETURN x.num`, which was null) and a path property other than `length`, `nodes` and `relationships` (`p.name`, which was null): `InvalidArgumentType`. A type error is an error, not a null: a subscript of a value that is not a list or map (`'abc'[0]`, `t.status[0]` on a string property, `$p[0]` with an integer `$p`) was null, now a TypeError (`a string cannot be indexed; only a list or a map can`); a list index that is not an integer (`[1, 2, 3][true]`, `[1, 2, 3][4.7]`) was null, now a TypeError (`list index must be an integer, got …`); a map key that is not a string (`{name: 'Apa'}[0]`) was null, now a TypeError (`map key must be a string, got …`); `range()` with an argument that is not an integer (`range('a', 5)`, `range(1, 2.5)`) was null, now an ArgumentError (`range() expects integer arguments, got …`); `properties()` of a value that is not a node, relationship, map or null (`properties(42)`, `properties($list)`) was null, now a TypeError (refused at compile time for a literal, `InvalidArgumentType`). A null base, index or argument is still null, and a subscript of a node, relationship or path variable still reads nothing. An unaliased scalar in `WITH` (`WITH t, t.location[1]`) still names itself. Planning errors (an unbound variable, a duplicate `RETURN` column) are now reported as `plan:` rather than `execute:` on every read entry point, since nothing has executed. The openCypher TCK pass rate rises from 52.8% to 60.2%, and the strict rate from 48.3% to 59.7%. (QL-VE)

### Fixed
- **Booleans compare: `false < true`.** `<`, `<=`, `>` and `>=` between two booleans gave null, so `WHERE n.flag > false` dropped every row and `min` / `max` over a boolean property gave null; openCypher orders `false` before `true`, as `ORDER BY` already did. A boolean and a value of another type still do not order (`true < 1` is null). Present in released 0.9.x (ledger row 160). (QL-VE)
