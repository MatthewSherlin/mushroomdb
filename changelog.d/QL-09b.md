### Added
- **Cypher clauses after `UNWIND`.** `UNWIND $rows AS r CREATE (:Person {id: r.id, name: r.name})` is the bulk-load idiom, and it works with `MERGE` (node and relationship forms, `ON CREATE SET` / `ON MATCH SET`), `MATCH … SET` (including `SET n += r`), `REMOVE`, `DELETE` and `DETACH DELETE`. The writes run per row and commit as one atomic batch (one WAL frame): a failure on any row writes nothing, a later row sees an earlier one (`UNWIND [1, 1] AS x MERGE (:N {id: x})` creates one node), and every write meets the usual checks. 10,000 `CREATE` rows take about as long as `ingest`. Reads after `UNWIND` work too: `UNWIND $ids AS id MATCH (n {id: id}) RETURN n`, and a map element is read with `r.id`. Not in an interactive transaction (refused by name); a read clause after a write clause is refused by name. (QL-09b).
