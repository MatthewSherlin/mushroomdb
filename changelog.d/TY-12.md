### Added

- **The five 0.10 value types, unique constraints and range indexes can now be stored: a store moves to the V11 snapshot format at its first use of one.** The first write that stores a `Date`, `LocalDateTime`, `DateTime`, `Duration` or `Binary` value — through any write path: Rust, Cypher, ingest, HTTP, Python, TypeScript — or that calls `create_constraint` or `enable_range_index`, first writes a V11 snapshot that keeps the WAL, then its record. On a large store that first write costs one full snapshot write. A group commit whose submissions carry the first such value upgrades before the group's first write, so a failed group fsync never leaves one of its submissions durable. V11 is sticky: every later snapshot is V11, even after the last constraint or range index is dropped. A store that never uses one keeps writing V9 (or V10), byte for byte what 0.9.x writes. **0.9.x cannot open a V11 store**: it stops with `snapshot: unsupported version 11` and leaves the WAL untouched, and there is no downgrade. 0.9.x `asof` on a V11 store refuses archive-resident commits as out of range rather than answer from archives it cannot fully read: a V11 store keeps its genesis-chain marker as `wal.genesis.v11`. A V11 snapshot carries its unique constraints, equality and range indexes and the multiplicity opt-in in a new, versioned section 18. Rust: `GraphDb::is_v11()`; `snapshot::version_for` now takes a `StoreFeatures`. See `docs/format-stability.md`.
- **A `DateTime` whose UTC offset is beyond ±18:00 is refused at the write**, however it was built, with `DateTime offset of N s is outside ±18:00`.
- **Python: a `datetime` with a nonzero `nanosecond` (a `pandas.Timestamp`) raises `ValueError`** instead of losing the nanoseconds.

### Changed

- **A snapshot version above 11 is refused with an upgrade hint:** `snapshot: unsupported version N — this store was written by a newer mushroomdb than this binary. To read it, upgrade your binary. Downgrade is not supported: see docs/format-stability.md.`
- **A role predicate (`visible_where`) holding a `Date`, `LocalDateTime`, `DateTime`, `Duration` or `Binary` value is refused with `<type> values cannot be used in a role predicate: roles.json carries no format version, so a 0.9.x reader would report it as corrupt`.**
