### Added
- **Restore from S3**: `mushroomdb restore --from s3://bucket/prefix [--at <commit | timestamp>] [--into <dir>]` restores a continuous backup into a new or empty directory (default `./restored`). Without `--at` it restores the newest restore point and the segments uploaded after it. `--at N` restores the store as it was right after commit N (numbered as `asof --commit` numbers them), and `--at <RFC 3339 timestamp>` the last commit at or before that instant, through the backup's `commit_times.bin`. A commit below the oldest one the backup holds, or a timestamp on a backup without commit times, is a clean error. Every file and segment is checked (size, CRC-32, generation, offsets, frames, lineage) in a staging directory before anything is written to the target, and a failed restore leaves the target untouched. The restored store gets a new backup lineage, so its backups never resume into, or delete from, the prefix it came from (ledger row 138)
