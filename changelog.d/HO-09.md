### Added
- **Restore from S3**: `mushroomdb restore --from s3://bucket/prefix [--at <commit | timestamp>] [--into <dir>]` restores a continuous backup into a new or empty directory (default `./restored`). Without `--at` it restores the newest restore point and the segments uploaded after it. `--at N` restores the store as it was right after commit N (numbered as `asof --commit` numbers them), and `--at <RFC 3339 timestamp>` the last commit at or before that instant, through the backup's `commit_times.bin`; an instant at or after the newest recorded time is refused when later segments hold commits with no recorded time, rather than answered with an earlier commit. A commit below the oldest one the backup holds, or a timestamp on a backup without commit times, is a clean error. Every file and segment is checked (size, CRC-32, generation, offsets, frames, lineage) in a staging directory before anything is written to the target, `commit_times.bin` is trimmed to the commits restored, and the staged store becomes the target in one directory rename, so a failed or interrupted restore leaves the target absent or empty, never a part of a store. The restored store gets a new backup lineage, so its backups never resume into, or delete from, the prefix it came from (ledger row 138)
