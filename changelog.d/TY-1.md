### Changed

- **A JSON object `{"$date": …}`, `{"$ldt": …}`, `{"$dt": …}`, `{"$dur": …}` or `{"$binary": …}` is now a typed value.** Through 0.9.x such an object was stored as a map. It now parses to a Date, LocalDateTime, DateTime, Duration or Binary value (ISO 8601 extended-format text — `2024-01-15`, `2024-01-15T12:34:56.789012`, `2024-01-15T12:34:56.789012+05:30` with an offset up to ±18:00, `P1Y2M3DT4H5M6.789S` — and padded base64 for binary), and a query that takes one as a parameter returns it in the same form. Storing one moves the store to the V11 snapshot format (see the V11 entry). Role predicates (`visible_where`) refuse the new types.
- **A one-key object under one of those five tags must be valid.** A payload that is not a string, or is not the tag's form (`{"$date": "2024-1-5"}`, `{"$date": "2023-02-29"}`, `{"$binary": "Zm9vYg"}`), is an error naming the field, the tag and the reason: a 400 for HTTP params and props, a tool error in MCP, and a row error in `ingest`. Through 0.9.x it was stored as a map. A bare string is still a string, and an object with another `$` key or more than one key is still a map. A store that already holds such a map exports it in that form, which now re-imports as the typed value or is refused.
- **Rust: `Value` has five new variants** (`Date`, `LocalDateTime`, `DateTime { micros_utc: i64, offset_seconds: i32 }`, `Duration`, `Binary`), so an exhaustive `match` on it needs new arms. `json_to_value` now returns `Result<Option<Value>, String>`. `tagged_text` and `tagged_json` give the wire forms.
