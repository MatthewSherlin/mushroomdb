### Added
- **Bolt returns nodes, relationships and paths as graph structures, and a write's summary carries its counters.** `RETURN n`, `RETURN r` and `RETURN p` arrive over Bolt as Node, Relationship and Path structures (in the 5.0 or 4.4 shape) with labels, type, properties and element ids (`n:<key>`, `r:<type>|<start>|<end>`), so a driver's `record["n"]["name"]`, `record["r"].type` and path objects work; `collect(n)`, `collect(r)`, `[a, b]` and `p.nodes` / `p.relationships` arrive as lists of them. Integer ids fit a JavaScript number: a node's is its dense id in the store (never reused, kept across a rename), a relationship's a 53-bit hash. A schema statement reports query type `s`; a role-bound connection sees only the nodes its role may see and no relationship to a hidden one. A write's closing `SUCCESS` carries `stats` (`nodes-created`, `relationships-deleted`, `properties-set` and the rest), which drivers read as `summary.counters`. In Rust, `ResultSet` gains `column_kind`, `entity` (inside `mushroomdb::with_entity_detail`) and `stats` (`WriteStats`). Ledger rows 148 and 149. (TX-NS)
### Changed
- **A fixed relationship variable can be returned bare.** `MATCH (a)-[r:KNOWS]->(b) RETURN r`, `WITH r`, a grouping key on `r`, `ORDER BY r` and `RETURN *` now include it; it renders on HTTP, in Python and in Rust as the map `{type, start, end}`, as a path's relationships do. `RETURN n` is unchanged everywhere but Bolt. `collect(r)` and `[r, s]` hold its maps (`collect(r)` was an empty list), and the `RETURN` of `MATCH … SET` / `REMOVE` can return it too. A variable-length relationship variable is still refused bare. (TX-NS)
### Fixed
- **`MERGE … ON CREATE SET` / `ON MATCH SET` counts its properties.** The write row's `properties_set` was 0 for a plain `MERGE` (node or relationship form, auto-commit or in a transaction) whatever it set; it now counts the items applied, as `UNWIND … MERGE` already did. Ledger row 150. (TX-NS)
