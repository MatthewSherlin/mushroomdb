### Added
- **`CREATE` and `MERGE` take parameters and expressions in their property maps.** `CREATE (:Person {id: $id, name: $p.name})`, `CREATE (n:Person $props)` and `MERGE (n:Person {id: $id}) ON CREATE SET n += $props` run auto-commit, inside a transaction, over HTTP `/query` and `/tx` and over Bolt, storing what the same statement with literal values stores (typed parameters keep their type; a null parameter value is left out; a null `MERGE` key is an error). `ON CREATE SET` / `ON MATCH SET` take the map forms `n += <map>` and `n = <map>`, and `$p.field` (or `$p['field']`) reads a map parameter's entry in any expression. The "use literals only" refusal is gone. (QL-PM)
