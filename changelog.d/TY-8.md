### Added

- **Rust: range indexes — `GraphDb::enable_range_index(name, label, field)`, `disable_range_index(name)` and `range_indexes()` — refused until the V11 format lands.** A range index on `(label, field)` keeps the field's values sorted, so the storage layer answers `<`, `<=`, `>`, `>=`, closed ranges and `STARTS WITH` as well as exact matches (`UnifiedIndex::lookup_range`, `lookup_prefix`, `lookup_eq`; `PropertyIndex` is now another name for `UnifiedIndex`). A lookup matches by type: an integer range never returns strings or floats, and a float range is numeric across zero. Existing nodes are indexed when the index is declared, and the index is rebuilt from the stored values at every open. It shares its entries with an equality index on the same pair: dropping the range index keeps an equality index or a unique constraint's index, and `disable_index` refuses a pair that only a range index covers. A range index cannot cover a property a view owns: `enable_range_index` refuses one, and `create_view` refuses a property a range index covers. Cypher queries do not use range indexes yet. The declaration is a new WAL record that 0.9.x cannot read, so until the V11 format lands `enable_range_index` fails with `not supported in mushroomdb 0.10 yet: range indexes cannot be declared until the V11 format lands` and the store is unchanged.
