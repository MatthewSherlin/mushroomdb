### Changed
- **A commit that rewrites or removes a full-text-indexed property now costs only the old value's words, not the whole vocabulary.** The index finds a node's old words by tokenizing the value being replaced. Before, every such commit walked every word the field had indexed. That cost grew with the store, and once the fold stopped rebuilding the index it made these commits 1.19–1.48× slower than v0.9.2. If the old value does not account for everything indexed for that node, the index falls back to the full walk, so search answers do not change. Single-node `name` commits on a `memory_defaults()` store, median, v0.9.2 → before → after: at 100k nodes, 1.99 → 2.61 → 0.068 ms with fsync off and 6.29 → 6.98 → 4.43 ms with fsync on; at 1M nodes, 17.0 → 23.8 → 0.080 ms with fsync off and 21.4 → 32.1 → 4.79 ms with fsync on. These numbers are provisional: they come from a loaded machine, and the quiet-machine release gate measures them again. New storage method: `FulltextIndex::remove_node_value`. (FT-1)
