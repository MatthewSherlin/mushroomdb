- **`mushroomdb export` writes CSV and Cypher, and `mushroomdb import` reads JSONL** (PF-04). `--format csv` writes `nodes.csv` and `relationships.csv` with typed headers (plus `rules.jsonl`), `--format cypher` writes `graph.cypher`, one `MERGE` statement per line that this engine's own `query` reads. `import --nodes-jsonl`, `--edges-jsonl` and `--rules-jsonl` (a path, or `-` for standard input) stream the JSONL export back in 50,000-node batches through the CSV import's batch path. An import of a CSV or JSONL export reproduces the store (nodes, properties, manual edges, rules and, once the rules are created, their derived edges), and the CSV importer gains `:KEY`, `date`/`localdatetime`/`datetime`/`duration`/`binary` and `json` columns to carry what the export writes. A JSONL node property named `key`, `label` or `$props` is no longer lost: it is written in a `$props` object. NaN and infinite floats, which neither JSON nor CSV can write, are counted in the export's output. The CSV column type `born:date` is now a typed column rather than an unknown suffix that stored a string.
