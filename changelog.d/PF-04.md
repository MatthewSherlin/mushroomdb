- **`mushroomdb export` writes CSV and Cypher, and `mushroomdb import` reads JSONL** (PF-04). `--format csv` writes `nodes.csv` and `relationships.csv` with typed headers (plus `rules.jsonl`), `--format cypher` writes `graph.cypher`, one `MERGE` statement per line that this engine's own `query` reads. `export --format jsonl --single-file` writes one `graph.jsonl` of `{"type":"node"|"edge"|"rule",…}` lines, and `import --jsonl` reads it (an edge must follow its nodes). `import --nodes-jsonl`, `--edges-jsonl` and `--rules-jsonl` (a path, or `-` for standard input) stream the JSONL export back in 50,000-node batches through the CSV import's batch path. An import of a CSV or JSONL export reproduces the store (nodes, properties, manual edges, rules and, once the rules are created, their derived edges), and the CSV importer gains `:KEY`, `date`/`localdatetime`/`datetime`/`duration`/`binary` and `json` columns to carry what the export writes. The JSONL, CSV and Cypher exports now stream (a 1M-node export peaks at the memory of opening the store). A JSONL node property named `key`, `label` or `$props` is no longer lost: it is written in a `$props` object, which changes the JSONL file of a store that has such a property. JSONL import now reads floats exactly (a float could come back one unit in the last place off). The Cypher export says how many nodes gain an `id` property. A property whose name or map key holds a line break is skipped by the Cypher export and counted in its output. NaN and infinite floats, which neither JSON nor CSV can write, are counted in the export's output. The CSV column type `born:date` is now a typed column rather than an unknown suffix that stored a string. The Rust API gains `GraphDb::for_each_node_for_export` and `GraphDb::for_each_edge_for_export`, which visit every node or edge one at a time instead of collecting them (read-only; the exports use them).
