### Changed
- **HTTP reads run on the lock-free reader and never wait on a writer.** `POST /query` (live reads, with or without a `mask` or `namespace`), `GET /node/{key}`, `GET /node/{key}/edges`, `GET /node/{key}/neighborhood`, `GET /health`, `GET /metrics` and `POST /algo/pagerank`, `/algo/wcc` and `/algo/degree` execute on a lock-free snapshot for every token. Capturing that snapshot no longer takes the read lock when a writer holds or awaits it — a Cypher write, `/ingest`, `create_rule`, a group commit: it reads the state the last writer released, which includes every write this process has returned. Another process's commits are picked up as before: the first capture after one applies it, waiting for the read guards already held. Answers and error bodies are unchanged, with one exception: a full-access read of a store whose unfolded commit tail cannot be applied now answers 500 naming the damage, as a role-bound read already did, where it answered 200 from live state. `as_of` reads, `/stats`, `/explain`, `/suggest`, `/find_similar` and the history routes still take the read lock. An equality lookup on a declared property index is served from the snapshot's own index — the fold's, with the nodes written since re-indexed over it — so indexed stores (every store `mushroomdb serve` and `mushroomdb mcp` create) get the same treatment. (TX-5).
- **Capturing a lock-free snapshot takes no lock in the common case.** `SharedDb::reader()` serves the snapshot the last writer published, without the read lock, while the store's files still match the state it was published at; concurrent readers' `stat`s are shared, one at a time, and skipped while a write guard is held. Readers no longer hold read guards a writer waits out, so a commit under concurrent readers no longer pays for them. Visibility is unchanged: a write this process returned and a commit another process returned are both in the next capture. (TX-5).
- **`ReaderSnapshot::deltas` is an `Arc<[Arc<CommitDelta>]>`** instead of a `Vec`, so handing out a snapshot touches one reference count, not one per delta. `len`, `is_empty`, `iter` and indexing work as before; `for d in &snap.deltas` becomes `for d in snap.deltas.iter()`. (TX-5).
- **A role-bound token's `/query` reads like a full-access token's.** It now accepts `UNION` / `UNION ALL` and reports a plan error as `execute: …`, as the full-access path always did. (TX-5).
- **`CommitDelta` and `FrozenOverlay` are `#[non_exhaustive]`** and gained the public fields `edge_props` and `prop_index`; they were never meant to be built outside `mushroomdb`. (TX-5).

### Fixed
- **The lock-free reader reads a weighted rule's recent scores.** A score a rule wrote or refreshed since the reader's last fold read as `null` through role-token `/query` and `SharedDb::reader()`; commit deltas now carry the edge properties a commit wrote. Ledger row 124. (TX-5).
