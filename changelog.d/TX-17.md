### Changed
- **A Bolt transaction begun with a role token or a `read` key now reads through the role, as an HTTP `/tx` transaction does.** `BEGIN` resolves the role's mask on the snapshot it freezes, and every statement reads through it there; before, every statement in such a transaction was refused. A write is refused with `Forbidden` and the text HTTP gives (`role-bound token: writes are not permitted inside a transaction`, or the `read` key's), whatever write scope the role carries (ledger row 140). A role the store no longer defines is `Unauthorized` at `BEGIN`. A new test runs the same reads and writes for two roles over two namespaces, a `read` key and the full token through HTTP `/query` and `/tx` and through Bolt, and compares every row, refusal and error kind. `docs/site/bolt.md` has a "Scoped access" section. (TX-17)
### Fixed
- **A write through `POST /query` by a role token whose role the store no longer defines is now 401, not 400**, matching a read through `/query`, `/tx/begin` and Bolt (`Unauthorized`). (TX-17)
