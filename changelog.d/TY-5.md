### Added

- **Rust: unique constraints — `GraphDb::create_constraint(name, label, field)`, `drop_constraint(name)` and `constraints()`.** A constraint makes every write that would give two live nodes of `label` equal values for `field` fail with `GraphError::ConstraintViolation` and write nothing, on every user write path (single writes, batches, compare-and-set batches, upserts, ingest, Cypher `CREATE` / `SET` / `MERGE`, `SharedDb`, and HTTP, which answers 409). The error names the constraint and the field, never the node already holding the value. Values compare as index keys, so two `DateTime`s at the same UTC instant are equal whatever their offsets. Declaring one creates the equality index on `(label, field)`, which `disable_index` refuses to drop while the constraint exists and which stays when the constraint is dropped. A constraint cannot cover a property a view owns: `create_constraint` refuses one, and `create_view` refuses a property a constraint covers. The declaration is a new WAL record that 0.9.x cannot read, so the first one moves the store to the V11 snapshot format (see the V11 entry).
- **A `Binary` value larger than 1 MiB (`BINARY_MAX_BYTES`) is refused with `GraphError::ValueTooLarge`** naming the property, its size and the limit (HTTP 413).
- **Rust: `GraphError` has three new variants** (`ConstraintViolation`, `ConstraintCreationConflict`, `ValueTooLarge`), so an exhaustive `match` on it needs new arms. Python raises them as `MushroomError`.
