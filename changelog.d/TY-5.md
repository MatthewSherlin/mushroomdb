### Added

- **Rust: unique constraints — `GraphDb::create_constraint(name, label, field)`, `drop_constraint(name)` and `constraints()` — refused until the V11 format lands.** A constraint makes every write that would give two live nodes of `label` equal values for `field` fail with `GraphError::ConstraintViolation` and write nothing, on every write path (single writes, batches, upserts, ingest, Cypher `CREATE` / `SET` / `MERGE`, `SharedDb`, HTTP, which answers 409). The error names the constraint and the field, never the node already holding the value. Values compare as index keys, so two `DateTime`s at the same UTC instant are equal whatever their offsets. Declaring one creates the equality index on `(label, field)`, which `disable_index` refuses to drop while the constraint exists and which stays when the constraint is dropped. The declaration is a new WAL record that 0.9.x cannot read, so until the V11 format lands `create_constraint` fails with `not supported in mushroomdb 0.10 yet: unique constraints cannot be declared until the V11 format lands` and the store is unchanged.
- **A `Binary` value larger than 1 MiB (`BINARY_MAX_BYTES`) is refused with `GraphError::ValueTooLarge`** naming the property, its size and the limit. Binary values themselves stay refused until the V11 format lands.
- **Rust: `GraphError` has three new variants** (`ConstraintViolation`, `ConstraintCreationConflict`, `ValueTooLarge`), so an exhaustive `match` on it needs new arms. Python raises them as `MushroomError`.
