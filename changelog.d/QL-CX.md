### Added
- **`MATCH … CREATE` and `MATCH … MERGE` run, once per matched row.** `MATCH (a {id: 'x'}), (b {id: 'y'}) CREATE (a)-[:K]->(b)`, with `WHERE`, `WITH`, `OPTIONAL MATCH` or `UNWIND` before the write, `SET` / `REMOVE` / `DELETE` beside it and `RETURN` after it, runs exactly as `UNWIND [1] AS _ MATCH … CREATE …` does: values are computed per row, the statement is one batch, and a `MATCH` that finds nothing writes nothing. A `MERGE` end may be a node an earlier clause bound, so `MATCH (a), (b) MERGE (a)-[:K]->(b)` finds or creates the relationship (in the `UNWIND` form too). Inside a transaction it is refused by name, as the `UNWIND` form is. QL-12 refused both forms by name. (QL-CX)
- **`RETURN *` and `WITH *`.** `*` stands for the node, path and value names in scope, in alphabetical order; further items may follow (`WITH *, n.age AS a`), and `RETURN DISTINCT *` works. Relationship variables are left out, since a relationship is not returned bare in 0.10. Also in the `RETURN` of write statements and after `CALL … YIELD`. With nothing in scope it is an error. (QL-CX)
- **Label predicates: `n:Label` and `r:TYPE` in any expression.** `WHERE n:Person OR n:Company`, `RETURN c:Company AS employed`, `WHERE NOT r:BLOCKS`. Three-valued (a null node gives null); it reads the label, not a stored `label` property, and is never turned into an index lookup. `n:A:B` and `n:A|B` stay refused by name: a node has one label. (QL-CX)
- **A query may begin with `OPTIONAL MATCH`.** It runs against one row, so `OPTIONAL MATCH (n:Missing) RETURN n` returns one row of nulls. (QL-CX)
### Fixed
- **A created relationship is counted in `created`.** `UNWIND … MATCH (a), (b) CREATE (a)-[:K]->(b)` created the edge and reported `created = 0`; a `MERGE` that created a relationship did not count it, and `CREATE (a:L {…})-[:K]->(b:L {…})` reported 2. `created` now counts the nodes and the relationships a statement creates, on every path (`CREATE`, `MERGE`, the per-row `UNWIND` forms and inside a transaction). The `UNWIND` forms were new in 0.10; on 0.9.x `created` was documented as nodes only, so `CREATE` of a chain reports one more per relationship than it did (ledger row 143). (QL-CX)
