### Added
- **CI runs the S3 backup tests for real.** The new `hosting-templates` workflow starts MinIO and runs every S3-gated test (the backup worker, the lease, `restore --from`, restore on boot, and `serve` with backup), on every push and pull request into `main` and `release/**`. It fails when any of them skips. Before this, no CI job started an S3 service, so these tests passed by skipping. `scripts/minio-smoke-test.sh` checks the built binary end to end: `serve`, writes, shipped to the bucket, `restore --from`, then restore on boot into an empty directory, with the node count checked each time. (HO-14).
- **The deploy templates are linted in CI.** `fly.toml` goes through `flyctl config validate --strict`, the Kubernetes manifest through kubeconform, and the Compose file through `docker compose config`. The Kubernetes manifest now shows `MUSHROOMDB_BACKUP_S3_URL` and `MUSHROOMDB_RESTORE_FROM_S3`, commented out, like the other templates. (HO-14).
### Fixed
- **The Fly template's check `grace_period` is 60 s**, the most Fly accepts. It said 120 s, which flyctl silently lowers to 60 s. A restore on boot that takes longer leaves the machine unhealthy until `/ready` answers (see deployment.md). (HO-14).
