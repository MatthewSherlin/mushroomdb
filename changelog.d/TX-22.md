### Added
- **Transactions and Bolt documentation.** A new [Transactions](docs/site/transactions.md) page covers the guarantees (one atomic commit, snapshot isolation, read-your-own-writes, rules and views at commit, rollback on crash), write skew and how to avoid it, which errors to retry, the server's limits, and examples in Rust, Python, HTTP, TypeScript and over Bolt. The Bolt pages now cover connecting an existing app, the supported driver features, the negotiated version per driver and what is not available over Bolt. Pages that still said there were no multi-statement transactions are corrected (TX-22).
### Fixed
- **TypeScript client: a unique-constraint refusal is no longer a transaction conflict.** A 409 with `code: "constraint"` now throws the new exported `ConstraintViolationError` (from a transaction's commit, which ends the handle, and from any auto-commit write such as `client.query`); `TransactionConflictError` is thrown only for a real conflict, which a retry can fix (TX-22).
- **HTTP transactions: an expiry says which limit ended it.** A transaction rolled back at its maximum lifetime now answers `410` with `transaction expired: open longer than its maximum lifetime, rolled back`; one rolled back for being idle keeps `transaction expired: idle too long, rolled back` (TX-22).
