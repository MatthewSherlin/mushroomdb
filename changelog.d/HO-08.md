- **Backup bucket lease**: continuous backup takes an advisory lease (`<prefix>/LEASE`) before uploading. A second instance on the same prefix uploads nothing, reports backup unhealthy naming the holder, and keeps checking every third of a TTL, so it takes over once the holder stops renewing (a crash, or a rolling deploy). On AWS S3, R2 and MinIO the lease uses conditional PUT, so two instances started together get exactly one lease. A probe at every acquire verifies that the service honors both `If-None-Match` and `If-Match`; if it does not, backup is refused, with the reason. A holder that cannot renew stops writing before its lease can be taken over. New variable `MUSHROOMDB_BACKUP_LEASE_CONDITIONAL` (`on` by default; `off` makes the lease best-effort, for services that reject conditional headers). `MUSHROOMDB_BACKUP_LEASE_TTL` must now be at least 1
- **One store per backup prefix**: the first backup of a store gives it a lineage (`backup.lineage`), and every manifest and object entry records it. A store pointed at a prefix that holds another store's backups is refused: it uploads nothing, deletes nothing, and reports why. So is a store restored from an older backup. Archives are reused only on a matching number, length and CRC. Retention deletes only the lineage's own objects, never the restore point it just wrote or `LATEST`'s target. Immutable objects are written with `If-None-Match`, and `LATEST` and manifests with `If-Match`, so the bucket refuses a stale writer. Manifest version 2 (ledger row 138)
