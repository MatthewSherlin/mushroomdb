### Fixed

- **A unique constraint now means what the query language's `=` means for numbers.** A constraint on a property refuses `2.0` beside `2` (and the reverse, and `-0.0` beside `0`), where it used to accept both and `MATCH (n {v: 2})` then returned both. Past 2^53 an integer equals the float it rounds to, and two integers are equal only when they are the same integer, as a query judges them. **Behaviour change:** a store that relied on `2` and `2.0` being different values under a constraint can no longer add the second one. A pair already stored cannot be declared over: `create_constraint` now refuses a store that already holds such a pair (see TY-6). Two `NaN`s used to conflict by bit pattern; `NaN` equals nothing, so they are now allowed.
- **An equality index over a property a view owns is refused (ledger row 123).** It answered from stale values until the store was reopened, so a query's answer changed with a reopen. `enable_index` now refuses a property a view owns, and `create_view` refuses a property an equality index covers. A store that already holds both opens, prints one `[mushroomdb] dropped the equality index on (label, field)` line to stderr per such index, drops it, and answers that property by scan (`GraphDb::dropped_view_indexes()` lists them); the next snapshot no longer carries the declaration.
