### Changed
- **A statement inside a transaction costs the same at any store size.** A transaction's own writes are now kept as a small private layer over its base snapshot. Each statement adds only its own records to that layer, and reads check the layer first. Before, every write statement copied store structures and rebuilt the full-text index. Measured on a loaded machine (provisional, median µs at 1k / 100k / 1M nodes, after 100 buffered statements): point read 8.5 / 9.5 / 10.5, 1-hop expand 13.9 / 17.2 / 20.0, property SET 7.3 / 8.6 / 9.4. Before the change, a SET took 180 / 13 333 / 176 624. Committing N ops through a transaction stays within the cost of `write_batch` for the same ops. Full-text matching (`textMatches`) inside a transaction sees the transaction's own text writes and deletes. (TX-1b)
- **A reader snapshot no longer rebuilds store state over its delta tail.** The commits since the last fold are read through the same kind of layer, built from the tail's own records. Before, the first read of each new snapshot copied the touched store structures and rebuilt the whole full-text index. Measured (provisional): a fresh reader's first point read with a 60-commit tail went from 10.6–15.0 ms to 0.04 ms at 100k nodes, and from 176–195 ms to 0.04 ms at 1M. With 16 readers and a writer setting the full-text-indexed `name` 50 times a second on a 100k-node `memory_defaults()` store, read p99 went from 0.8–1.1 s to 1.87 ms (median of 6 runs, twice). `FrozenOverlay` no longer has a `fulltext` field: no reader read it, and sharing the writer's index made the writer's first full-text write after each fold copy the whole index while holding the write lock. (TX-1b)
