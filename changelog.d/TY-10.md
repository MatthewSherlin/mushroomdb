### Added

- **Cypher answers ranges, `STARTS WITH` and `ORDER BY … LIMIT` from a range index.** With a range index on `(Label, prop)`, `MATCH (n:Label) WHERE …` reads the index for an `AND`-ed `n.prop < | <= | > | >= x` (either way round, two of them making a range) or `n.prop STARTS WITH x`, where `x` is a literal or a `$parameter`; and `MATCH (n:Label) RETURN … ORDER BY n.prop [DESC] [SKIP s] LIMIT k` — with no `WHERE`, or one made only of such a range on the same property — reads the index in sort order and stops once the first `SKIP + LIMIT` rows and their ties are known (a descending sort with no `WHERE` also walks the label once for the nodes without the property, which sort first). The answer is the scan's, row for row and in the same order: integers and floats compare as numbers, a string bound finds only strings, temporal values range in their own order, and a node without the property sorts where `ORDER BY` puts it (last ascending, first descending). A `Duration`, `Bool`, list or `null` bound, `n.key`/`n.id`/`n.label`, a pattern across a relationship, a transaction and a reader with an unfolded commit tail scan instead, with the same answer. The plan op is `IndexRangeScan`.
