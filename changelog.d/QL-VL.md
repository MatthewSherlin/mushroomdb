### Fixed
- **A variable-length hop ignored its destination's label and properties.** `MATCH (a)-[*1..3]->(b:Person {active: true})` returned every node reachable within three hops, whatever its label or `active` value; it now returns only the `Person` nodes with `active: true`. The nodes a path passes through are still not filtered. This holds in every hop form, for a hop in the middle of a pattern, with a named path and with parameters in the map. A `shortestPath` destination's label and properties are now checked too, and `OPTIONAL MATCH` accepts a variable-length hop. Writes driven by such a MATCH landed on the same wrong nodes: on 0.9.x `MATCH (a {id: 'a'})-[*1..3]->(b:Person {active: false}) DETACH DELETE b` deleted every node reachable within three hops, and `MATCH … SET` changed them all. Present in released 0.9.x (ledger row 132).
