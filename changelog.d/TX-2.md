- **Python write calls no longer hold the GIL across the WAL fsync (ledger row 65).** Every method that takes the store lock (`insert_node`, `upsert_node`, `set_prop`, `set_props_many`, the edge writes, `remember`, `upsert_entity`, `forget` and the rest, plus reads) now releases the GIL while it waits for and holds the store, so other Python threads run during a commit. `upsert_node` reads and writes in one engine call, so concurrent upserts of one key stay atomic.
