### Added

- **Cypher `null` literal and nulls inside lists and maps**: `RETURN null`, `WHERE null IS NULL`, `[1, null, 'a']`, `{a: null}` and `[n.x, n.missing]` now evaluate instead of failing. A null element stays null in every output: `Value::Null` in Rust, `null` in HTTP JSON and TypeScript, `None` in Python, `[1, null]` in Arrow's list text. `size([null])` is 1, `head([null, 1])` is null and `keys({a: null})` is `['a']`. `null` is reserved like `true` and `false`, so it cannot name a variable or an alias; `n.null` and a backtick-quoted `` `null` `` key still work. `Value` gains a `Null` variant, so a Rust `match` over `Value` needs a new arm.
- **Cypher queries without `MATCH`**: a read may begin with `RETURN`, `UNWIND` or `WITH`. `RETURN 1 + 1 AS x`, `UNWIND [1, 2, 3] AS x RETURN x` and `WITH 1 AS a RETURN a` run against one empty row and read nothing from the graph.

### Changed

- **A stored property still cannot be null**: writing a list or map property that holds a null, whether from `CREATE (:L {p: [1, null]})`, `SET n.p = [1, n.missing]`, a `$param` or the Rust API, is refused with `a property value cannot contain null`, and nothing is written. Before this change, a null element was a query error even in a read.
