### Added
- **Cypher `SET n = {…}` and `SET n += {…}`.** `MATCH … SET n += {k: v, …}` sets the listed properties and leaves the rest (a `null` value removes that property); `SET n = {…}` replaces the node's user properties with exactly the map. Both go through the ordinary write path in one WAL frame, so rules re-evaluate every set and removal and unique constraints apply. `id`, `ns` and view-owned properties are never removed by `=`; a map that changes `id` or `ns`, or names a view-owned property, is refused. Map values may be expressions and `$parameters`; the map itself must be a literal. Inside an interactive transaction the map forms are refused by name. (QL-06).
