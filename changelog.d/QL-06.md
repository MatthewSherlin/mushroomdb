### Added
- **Cypher `SET n = {…}` and `SET n += {…}`.** `MATCH … SET n += {k: v, …}` sets the listed properties and leaves the rest (a `null` value removes that property); `SET n = {…}` replaces the node's user properties with exactly the map. Both go through the ordinary write path in one WAL frame, so rules re-evaluate every set and removal and unique constraints apply. `id`, `ns` and view-owned properties are never removed by `=`; a map that changes `id` or `ns`, or names a view-owned property, is refused. Map values may be expressions and `$parameters`; the map is a literal or a `$parameter` holding a map, and a parameter that is not a map is an error. `MERGE … SET n = {…}` is refused by name. Inside an interactive transaction the map forms are refused by name. (QL-06).

#### BREAKING
- **`SET n.id` and `REMOVE n.id` are refused; use the rename API to change a key.** `id` mirrors the node's key, and `SET n.id = 'other'` used to change the property without renaming the key, so the two diverged (ledger row 128). Restating the key (`SET n.id = 'alice'` on alice) is still a no-op. `rename_node` (Rust, Python, MCP) renames the key and moves a matching `id` with it. (QL-06).
