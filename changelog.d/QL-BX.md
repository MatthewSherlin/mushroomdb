### Added
- **Cypher comparisons and boolean operators work in every expression position.** `=`, `<>`, `<`, `<=`, `>`, `>=`, `IS [NOT] NULL`, `IN`, `STARTS WITH`, `ENDS WITH`, `CONTAINS`, `NOT`, `AND`, `OR` and the new `XOR` now parse in `RETURN` and `WITH` items, `ORDER BY`, list and map elements, list comprehensions, `reduce`, function arguments, `CASE` branches, `SET` values and per-row `CREATE` / `MERGE` properties, not only in `WHERE`: `RETURN n.age >= 18 AS adult`, `[x IN l | x > 1]`, `SET n.flag = n.score > 10`. As a value a predicate is three-valued (`RETURN null > 1` is null, `NOT null` is null, `null IS NULL` is true). Precedence follows openCypher, and parentheses now group arithmetic inside a `WHERE` too (`WHERE (n.age + 1) > 18`). A `WHERE` that parsed before parses to the same predicate and filters exactly as before.
