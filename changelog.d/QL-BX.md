#### BREAKING

- **A WHERE predicate that evaluates to null now filters the row, including under NOT.** `WHERE`, `CASE WHEN` and a list comprehension's `WHERE` evaluate three-valued, as openCypher does: `WHERE NOT n.x = 1` no longer returns the nodes that have no `x`, and `WHERE NOT (a AND null)` drops a row whose `a` is true. Before, a comparison with a null side read as false and `NOT` turned it into true, so these queries returned extra rows (defect ledger row 133, present in 0.9.x). A write statement's `WHERE` writes only the rows a read keeps. Queries without a `NOT` over a null return what they did.
- **Expressions nest at most 64 levels deep.** Parentheses, function arguments, list and map elements and `CASE` branches count together; deeper input is the named parse error `expression nesting too deep`. Function-call and `RETURN` parenthesis nesting had no limit before (very deep input could overflow the stack); `WHERE` parentheses and literals were already capped at 64 each.

### Fixed
- **`IN` compares a list element whole.** `x IN [[1, 2], 3]` used to read as `x IN [1, 2, 3]`: `n.x IN [$l]` matched an element of `$l`, and `n.tags IN [$t]` never matched a node whose `tags` equals `$t` (defect ledger row 135, present in 0.9.x). Now `[1, 2] IN [[1, 2]]` is true, `1 IN [[1]]` is false and `null IN [[]]` is null. The right-hand side of `IN` is an additive expression, so `x IN [1, 2] + [3]` parses.

### Added
- **Cypher comparisons and boolean operators work in every expression position.** `=`, `<>`, `<`, `<=`, `>`, `>=`, `IS [NOT] NULL`, `IN`, `STARTS WITH`, `ENDS WITH`, `CONTAINS`, `NOT`, `AND`, `OR` and the new `XOR` now parse in `RETURN` and `WITH` items, `ORDER BY`, list and map elements, list comprehensions, `reduce`, function arguments, `CASE` branches, `SET` values and `CREATE` / `MERGE` properties (a plain `CREATE (n:T {id: 'x', flag: 1 > 0})` evaluates a constant expression before the write, and `MERGE` matches against the evaluated value), not only in `WHERE`: `RETURN n.age >= 18 AS adult`, `[x IN l | x > 1]`, `SET n.flag = n.score > 10`. As a value a predicate is three-valued (`RETURN null > 1` is null, `NOT null` is null, `null IS NULL` is true). Precedence follows openCypher, and parentheses now group arithmetic inside a `WHERE` too (`WHERE (n.age + 1) > 18`). A `WHERE` that parsed before parses to the same predicate.
