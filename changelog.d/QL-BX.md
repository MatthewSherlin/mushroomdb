#### BREAKING

- **A WHERE predicate that evaluates to null now filters the row, including under NOT.** `WHERE`, `CASE WHEN` and a list comprehension's `WHERE` evaluate three-valued, as openCypher does: `WHERE NOT n.x = 1` no longer returns the nodes that have no `x`, and `WHERE NOT (a AND null)` drops a row whose `a` is true. Before, a comparison with a null side read as false and `NOT` turned it into true, so these queries returned extra rows (defect ledger row 133, present in 0.9.x). A write statement's `WHERE` writes only the rows a read keeps. Queries without a `NOT` over a null return what they did.

### Added
- **Cypher comparisons and boolean operators work in every expression position.** `=`, `<>`, `<`, `<=`, `>`, `>=`, `IS [NOT] NULL`, `IN`, `STARTS WITH`, `ENDS WITH`, `CONTAINS`, `NOT`, `AND`, `OR` and the new `XOR` now parse in `RETURN` and `WITH` items, `ORDER BY`, list and map elements, list comprehensions, `reduce`, function arguments, `CASE` branches, `SET` values and per-row `CREATE` / `MERGE` properties, not only in `WHERE`: `RETURN n.age >= 18 AS adult`, `[x IN l | x > 1]`, `SET n.flag = n.score > 10`. As a value a predicate is three-valued (`RETURN null > 1` is null, `NOT null` is null, `null IS NULL` is true). Precedence follows openCypher, and parentheses now group arithmetic inside a `WHERE` too (`WHERE (n.age + 1) > 18`). A `WHERE` that parsed before parses to the same predicate.
