### Added
- **Restore on boot**: set `MUSHROOMDB_RESTORE_FROM_S3=s3://bucket/prefix` on `serve` to restore automatically on an empty volume. When the data directory holds no store, the newest restore point is restored before the store is opened and the port is bound. It takes the bucket lease first, and exits 1, naming the holder and writing nothing, while another instance holds a fresh one. A prefix with no backup starts an empty store with a warning, so a template's first deploy works. Any other failure (a missing, damaged or partial backup, a refused credential, a network failure) exits 1 and serves nothing, and leaves the data directory without a store. A directory that already holds a store is never restored over. The restore installs in place, inside the data directory, so it works on a volume's mount point. It installs under a marker, which the next boot uses to undo an install a crash interrupted. The restored store is a new lineage that records the restore point it came from. Its backup continues under the same prefix, under the lease the restore took, beside the parent's restore points, which are never overwritten or deleted by retention (ledger row 138). ### Fixed
- **`restore --from`** no longer fails where the filesystem has no advisory locks, and no longer leaves its lock file behind when locking fails. A restore that finds no backup no longer removes killed restores' leftovers. A starting restore's lock file is never removed by a concurrent restore's sweep, and the sweep runs off the async runtime
