mushroomdb

The graph that stays true — and knows who's allowed to see it.

An embedded Rust graph database where edges are a schema declaration: write a rule once, and every write creates, maintains, and retracts the matching edges. Ships a 16-tool MCP server.

Pre-1.0 alpha — APIs and formats may change between minor versions.

npx mushroomdb install

Writes the /mushroom skill, the MCP server entry, and the recall hook for Claude Code or Cursor.

Declare the rule. The edges maintain themselves.

A rule is a schema object, not a script you re-run: connect every Person to every Org whose skills overlap theirs by at least 50%, written once. Every insert and every property change evaluates it incrementally, stores the score on the edge, and retracts the edge when the properties stop matching.

Every derived edge shows its arithmetic.

explain names the rule, the field values that matched, and the computed score behind any link. An assistant answering "why are these two related?" can quote the derivation instead of guessing, and the same why panel is built into the bundled graph explorer.

Point it at a repository and watch it stay current.

mushroomdb ingest-git graphs authors, commits, and files, then derives co-change and ownership edges by rule. Re-run it to sync: only new commits replay, deleted files drop their derived edges, and renamed files carry their history to the new path.

Where it fits

What it is

  • An embedded, single-binary graph database with a rule engine that maintains edges for you.
  • A 16-tool MCP server plus a /mushroom skill for Claude Code and Cursor.
  • Local-first: your data stays on disk, no cloud service, no LLM in the write path.

What it isn't

  • Not a hosted memory service — no account, no endpoint, nothing to sign up for.
  • Not a vector database. Vector predicates and HNSW are built in; bring your own embeddings.
  • Not a Postgres replacement. Single writer, no interactive transactions, memory-first storage.
