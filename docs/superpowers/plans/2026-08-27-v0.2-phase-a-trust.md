# v0.2 Phase A — Trust (migration + format promise + benchmarks-in-CI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make it safe to trust mushroomdb with real data: old stores migrate forward automatically and reversibly, the format promise is written down, and performance regressions fail CI.

**Architecture:** Two tasks. Task 1 adds migrate-on-open + a `mushroomdb migrate` CLI + the format-stability contract doc. Task 2 adds a benchmarks-in-CI job with a committed baseline and a ±15% regression gate.

**Tech Stack:** In-tree Rust only; no new crates. CI = existing GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-27-v0.2-association-engine.md` §Phase A / Gate GA

**Interfaces:**
- Produces:

```rust
#[derive(Clone, Copy, Debug)]
pub struct OpenOptions {
    /// Rewrite an old-format snapshot to the current VERSION after a
    /// successful load (default true). The old snapshot is kept as
    /// `snapshot.bin.bak` until the next clean open.
    pub auto_migrate: bool,
}
impl Default for OpenOptions { fn default() -> Self { Self { auto_migrate: true } } }

impl GraphDb<RealFs> {
    pub fn open_with_options(dir: &std::path::Path, opts: OpenOptions) -> Result<Self>;
    // open(dir) == open_with_options(dir, OpenOptions::default())
}
/// Returns the on-disk snapshot format version (None if no snapshot).
pub fn snapshot_version_at(dir: &std::path::Path) -> Result<Option<u16>>;
```

- Behavior (binding):
  - After a successful load where the decoded snapshot version < current `VERSION`: copy the existing `snapshot.bin` to `snapshot.bin.bak` (via fs primitives, fsynced), then `snapshot_with(SnapshotOptions { keep_wal: true })`. On any migration error, the store stays usable on the old format (log-and-continue is NOT allowed — return the error; the original files are intact).
  - A clean open that finds the CURRENT version and a leftover `.bak` deletes the `.bak`.
  - `auto_migrate: false` → open behaves exactly as today (pin with a test asserting the on-disk version is unchanged after open).
  - WAL-only stores (no snapshot) are NOT migrated on open (nothing to rewrite; replay already produces current in-memory form). CLI migrate on such a store performs a normal truncating `snapshot()`.
  - CLI: `mushroomdb migrate <dir>` prints `migrated V<from> -> V<current>` (or `already current (V<current>)`), performs the truncating snapshot path, keeps `.bak`.

fn store_from_fixture(name: &str, bytes: &[u8]) -> std::path::PathBuf {

#[test]
fn v5_store_auto_migrates_on_open_with_bak() {
    let dir = store_from_fixture("v5", include_bytes!("fixtures/golden_v5.bin"));
    {
        let db = GraphDb::open(&dir).unwrap();
        assert_eq!(db.node_count(), 2);
    }
    // on-disk snapshot is now current VERSION; .bak holds the old bytes
    assert_eq!(core_api::snapshot_version_at(&dir).unwrap(), Some(core_storage::snapshot::VERSION));
    let bak = std::fs::read(dir.join("snapshot.bin.bak")).unwrap();
    assert_eq!(u16::from_le_bytes([bak[4], bak[5]]), 5, ".bak must be the original v5 bytes");
    // data survives the migration
    let db = GraphDb::open(&dir).unwrap();
    assert_eq!(db.get_prop("a", "v"), Some(&Value::Int(42)));
    // second clean open removed the .bak
    assert!(!dir.join("snapshot.bin.bak").exists());
}
