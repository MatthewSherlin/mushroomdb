# v0.2 Phase B — Storage Physics (mmap zero-copy + MVCC readers) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Open a multi-GB store in under 100 ms with bounded RSS, and give readers a lock-free path that never blocks behind the writer.

**Architecture (pinned — deviations need a controller ruling):**
- **V8 snapshot = one mmap-able file** of rkyv-archived sections behind a header/directory page. Read-only `memmap2` map; per-section checksums validated lazily on first touch; little-endian pinned.
- **Base + overlay:** the mapped V8 file is the immutable BASE; all post-snapshot state (WAL-tail replay and live writes) lives in an in-memory OVERLAY (the current owned structs, reused). Every read consults overlay-then-base. `snapshot()` merges base+overlay into a new V8 file, rename-swaps (Phase A safety rail), remaps, clears overlay.
- **MVCC = epoch-published commit deltas:** each commit appends an `Arc<CommitDelta>` to a chain; a reader snapshot = (base map Arc, chain prefix). Chain folds into a merged overlay every K=64 commits and at snapshot, bounding read overhead. Writer stays single; readers never take the write lock.
- V5–V7 stores keep the existing owned decode path and reach V8 through Phase A's migrate-on-open rail. VERSION bumps to 8; golden pins for 5/6/7 stay green; a golden_v8 pin is added.

**Tech Stack:** Adds exactly two crates, sanctioned by the spec: `rkyv = "0.8"` and `memmap2`. Nothing else.

**Spec:** `docs/superpowers/specs/2026-08-27-v0.2-association-engine.md` §Phase B / Gate GB

## Global Constraints

- Gate GB numbers are the arbiter (measured on the 2.2 GiB / 100k dogfood store, recorded in `dogfood/results/scale-100k.md`): open-to-first-query **< 100 ms** (warm file cache, cold process; cold-cache number reported alongside), RSS after open + Big-3 query slice **< 500 MiB**, 8 concurrent readers under write burst p95 < 2× single-reader baseline.
- `cargo test --workspace --offline` (after the one-time dep fetch), fmt, clippy zero-warnings after every task. Cargo bin: `$HOME/.rustup/toolchains/1.92.0-aarch64-apple-darwin/bin`.
- WAL replay identity, DST crash sweeps, and oracle equivalence stay green throughout — replay builds the overlay deterministically over the base.
- NEVER a writable mmap. Mutations go through the WAL exactly as today; the mapped file is read-only; snapshot writes go write-new → rename-swap.
- Query results must be byte-identical between an all-owned store and a base+overlay store with the same logical content (equivalence tests are mandatory per task).
- golden_v5/v6/v7 pins untouched; `format-stability.md` updated (V8 entry + migrator note) in the task that bumps VERSION.
- GraphError append-only. Conventional lowercase commits, no Co-Authored-By.

### Task 1: V8 archived format + mmap read path (topology, columns, ids, interns)

**Interfaces (produces — later tasks build on these exact names):**

```rust
// core-storage/src/v8/mod.rs
pub const V8_MAGIC_SECTION_COUNT: usize; // header directory entries
pub struct MappedBase { /* Mmap + directory + OnceLock-validated sections */ }
impl MappedBase {
    /// mmap the file, validate ONLY the header page. O(1), no data read.
    pub fn map(path: &Path) -> Result<Self>;
    pub fn topology(&self) -> Result<&ArchivedCsr>;      // checksum-on-first-touch
    pub fn columns(&self) -> Result<&ArchivedColumns>;
    pub fn ids(&self) -> Result<&ArchivedIdMap>;
    pub fn syms(&self) -> Result<&ArchivedInterner>;
    // Task 2 adds: edge_props(), hnsw(), provenance(), rules_meta(), views()
}
// View seams (overlay-then-base); overlay = the EXISTING owned structs:
pub struct TopologyView<'a> { pub overlay: &'a Topology, pub base: Option<&'a ArchivedCsr> }
impl TopologyView<'_> { pub fn neighbors(&self, etype: u32, id: u32, dir: Direction) -> MergedNeighbors<'_>; pub fn edge_count(&self) -> u64; /* mirrors every Topology read API used by core-query/core-rules */ }
pub struct ColumnsView<'a> { pub overlay: &'a ColumnStore, pub base: Option<&'a ArchivedColumns> }
impl ColumnsView<'_> { pub fn get(&self, id: u32, field: &str) -> Option<ValueRef<'_>>; pub fn vector(&self, id: u32, field: &str) -> Option<&[f64]>; }
```

Design bindings:
- rkyv 0.8, LE-pinned (`#[rkyv(...)]` archived types); sections written 8-byte aligned; directory in the first 4 KiB: `{section_id, offset, len, crc32}` entries; whole-header crc.
- Deletions vs base: overlay tombstones. `TopologyView::neighbors` merges overlay adjacency with base adjacency MINUS overlay-deleted edges; `MergedNeighbors` iterates sorted-unique (determinism).
- `ValueRef<'_>` borrows either an overlay `&Value` or materializes from archived scalars — equality/comparison semantics identical to `Value` (equivalence-tested).
- Encode: `snapshot::encode_v8(base: Option<&MappedBase>, overlay: &...) -> streamed file write` — merge iterators, never a full owned clone of the base (RSS during snapshot must stay bounded; document measured peak).
- Decode dispatch: VERSION=8 → `MappedBase` handle returned to core-api; V5-V7 → existing owned `SnapshotState` path unchanged.
