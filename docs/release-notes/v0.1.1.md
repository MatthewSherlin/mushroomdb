## What's new

### Cypher language additions

Three Cypher features close the most-requested gaps reported since v0.1.0:

| Feature | Example |
|---|---|
| `IS NULL` / `IS NOT NULL` | `OPTIONAL MATCH (a)-[r]->(b) WHERE b IS NULL RETURN a` — the anti-join idiom |
| General arithmetic (`+`, `-`, `*`, `/`) | `RETURN n.age + 1`, `WHERE n.score * 2 > 10`, `SET n.x = n.x + 1` |
| `CREATE … RETURN` and `MERGE … RETURN` | `CREATE (n:Person {id: 'x'}) RETURN n.id AS id` — write + project in one statement |

`IS NULL` enables the full `OPTIONAL MATCH … WHERE b IS NULL` anti-join pattern.
Arithmetic has correct precedence (`*`/`/` before `+`/`-`), parenthesis support, null
propagation, and a named error on integer division by zero.
`CREATE … RETURN` and `MERGE … RETURN` commit the write before projecting, making
single-statement upsert-and-return round-trips possible.

### Snapshot format V6 (compressed)

`snapshot()` now writes a **zstd level-3 compressed** V6 container. At 100k nodes
(~10.5M derived edges):

| Metric | V5 (v0.1.0) | V6 (v0.1.1) | Change |
|---|---|---|---|
| Snapshot size | ~2.2 GiB | **1.1 GiB** | −50% |
| Write (`snapshot()`) | 25.09 s | **22.563 s** | −10% |
| Open (`open_with`) | 8.71 s | **8.880 s** | +2% (decompression overhead) |

V5 snapshots are read transparently — no migration required. Old binaries cannot read
V6 files (the wire format is forward-breaking for the snapshot file only; WAL format,
Python bindings, and the HTTP API are unchanged).

### `snapshot_with(SnapshotOptions { keep_wal: bool })`

New API to control WAL retention after a snapshot. `keep_wal: true` writes the V6
snapshot but does not truncate the WAL, keeping pre-snapshot commits reachable via
`open_at`. Crash-safe: the snapshot write is atomic; if it crashes the full WAL is
intact and replay over the snapshot is idempotent. `snapshot()` is unchanged
(`keep_wal` defaults to false).

### MCP agent-memory tools

Three new MCP tools for agent workflows, available via `mushroomdb mcp <dir>`:

| Tool | Description |
|---|---|
| `upsert_entity` | Insert or update a node by key with no existence check; creates if absent, updates properties if present |
| `find_similar` | Return neighbors connected by a given edge type (default `SIMILAR`); designed for vector-rule recall in agent-memory workflows |
| `explain_association` | Explain rule-derived associations between two node keys; returns rule name, edge type, and match score per link |

The MCP server now exposes eleven tools total. See
[`docs/site/mcp.md`](../site/mcp.md) for the Claude Desktop configuration and the
full agent-memory quickstart (store → link → recall → explain).

### 100k cold-start trio (V6 snapshot)

Dataset: 100,000 nodes (70k Talent, 20k Company, 10k Job, 500 User), 9 backfill rules,
~10.5M derived edges.

| Phase | v0.1.0 (V5) | v0.1.1 (V6) | Notes |
|---|---|---|---|
| Backfill (9 rules, max_edges=1M each) | 28.65 s | **20.343 s** | No rule engine changes; measurement-day variance |
| V6 snapshot write | 25.09 s | **22.563 s** | zstd compression; smaller output |

## Breaking changes

**Snapshot format V6 is forward-incompatible.** v0.1.0 binaries cannot open V6 snapshot
files. The upgrade path:

1. Build v0.1.1.
2. Open your existing v0.1.0 database with the new binary — V5 snapshots are read transparently.
3. Call `snapshot()` (or `snapshot_with(...)`) to write a V6 snapshot.
4. The new snapshot is now the active state. Old v0.1.0 binaries cannot open it.

WAL format is unchanged. Python bindings, HTTP API, and the WebSocket subscription API
are unchanged.

## Limitations carried forward from v0.1.0

See [v0.1.0 release notes](v0.1.0.md) for the full limitation table. The following
limitations from v0.1.0 are unchanged in v0.1.1:

- RAM-bound storage (no mmap).
- No multi-statement transactions; no isolation within a batch.
- Combined `MATCH … SET … RETURN` in one statement is rejected (named error).
- `MERGE ON CREATE SET` / `ON MATCH SET` clauses are not supported.
- Dense variable-length paths producing >1,000,000 intermediate rows abort with a named error.
- `demo` refuses non-empty directories.
