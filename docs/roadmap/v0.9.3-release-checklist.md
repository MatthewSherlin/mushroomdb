# v0.9.3 — the steps only a person takes

Prepared on 2026-10-22. 0.9.3 carries one fix, ledger row 139, backported from 0.10 onto `main`
(v0.9.2 plus the docs-only 0.10 spec merge, `1200cdfe`). It arrives in one pull request with
three commits: the fix, the ledger row, and the commit that sets every version site to 0.9.3.
Nothing has been tagged or published.

**What the green does and does not prove.** Every local result is from one macOS machine: the
workspace suite ran with the child-process kill tests skipped (`crash_before_commit`, `killed`,
`abort`, `crash`), which hang on that host; CI runs them. The seven tests in
`crates/core-api/tests/fused_scan_base.rs` fail on `1200cdfe` and pass with the fix. The timing
in row 139 is provisional: one machine, also running other work. Not run by anyone: the test
suite on Windows. No independent review of the backport has run yet.

## Before anything leaves this machine

A tag freezes each of these. Each is in force on the branch; tick it to accept, or change it first.

- [ ] **D1 — this is 0.9.3, a patch release, and it carries row 139 only.** Nothing else from
      `release/0.10`. No format version change: the fix is read-side only, so 0.9.2 opens a 0.9.3
      store and 0.9.3 opens a 0.9.2 one.
- [ ] **D2 — `mushroomdb-storage` keeps its 0.9.2 API.** The new base-aware handle is an added
      method, `ColumnsView::view_column`; the overlay-only `ColumnsView::column` keeps its
      signature and is deprecated. (0.10 changes `column` itself, which a minor version allows.)
- [ ] **D3 — measured cost** (release build, 100k nodes, `WHERE n.val <> 3 … LIMIT 1000000`,
      median of 21): no snapshot 13.6 ms before, 13.3–15.1 ms after; after a snapshot 0.10 ms
      and **0 rows** before, 12.1–13.4 ms and the right 90,000 rows after.
- [ ] **D4 — deferred to 0.10:** rows 44, 51, 54, 62, 63, 64, 65, 66, 67, 69, 70, 85, 88, 90, 101,
      102, 114 (seventeen; their targets read 0.10 now, since 0.9.3 does not carry them).
- [ ] **D5 — the ledger has a gap.** Row 139 follows row 116 on `main`; rows 117–138 are the 0.10
      ledger's. `check-defect-ledger.sh` counts rows and does not require them to be contiguous.
      Merging `main` into `release/0.10` will conflict on the ledger and on the version sites;
      `release/0.10`'s copy of row 139 should then say "CLOSED in 0.9.3 and 0.10".
