# W5 — Performance, bulk import, and published proof — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix key-anchored traversal (row 102 < 1 ms p50 at 1M nodes), add CSV/JSONL bulk import and export, publish a reproducible benchmark suite and generated performance page, and back every data-safety claim with a named CI job — closing ledger rows 46, 62, and 102.

**Architecture:** The planner fix (`fold_key_anchor_after_expand`) is a new post-pass in `plan.rs` that rewrites `ScanLabel→Expand→Filter(key=val)` to `ScanKey→Expand`; no executor changes are needed because the `ScanKey` arm already calls `db.node_by_key()` (O(1) IdMap lookup). Bulk CSV import is a new CLI subcommand (`mushroomdb import`) that drives the existing `GraphDb::ingest` / `ingest_with_edges` batching path with rule evaluation deferred to a single post-import backfill. The performance page and data-safety page are generated from result JSON sidecars and verified by a CI drift check; every claim on the data-safety page names an existing CI job.

**Tech Stack:** Rust (workspace), `csv` crate (approved §9.1) for CSV parsing, Python 3 for benchmark scripts, criterion 0.8 for micro-benchmarks, existing `mushroomdb` Python wheel for the query-shape CI gate.

**Spec:** `docs/roadmap/v0.10-spec.md` and `docs/roadmap/v0.10/W5-performance-proof.md`

## Review Focus

The five failure modes most likely to slip through unit tests, each pinned to the task that must exercise them:

1. **Planner rewrite produces wrong results when residual predicates remain after key fold** — `WHERE key(n) = $k AND n.score > 5` must still filter by `n.score > 5`; pinned to Task 1 Step 1 (differential probe (c)).
2. **WAL replay after key-anchored fix returns different rows than a fresh store** — the fold is planner-only but the planner runs on WAL replay; incorrect register of `ScanKey` on replay returns 0 rows; pinned to Task 1 Step 1 (differential probe (a)).
3. **CSV import silently truncates rows when delimiter appears inside a quoted field** — RFC 4180 correctness; pinned to Task 6 Step 1 (header-parsing unit tests for quoted fields).
4. **fsync integrity test passes on a runner that uses tmpfs** (where fsync is a no-op) — the test must assert the node survives `exit(0)`, not just that the write returns; pinned to Task 2 Step 1 (the test opens the store in a second invocation and reads the node, not just asserts write succeeds).
5. **Performance page drift goes undetected when result files are manually edited** — `render_perf_page.py` must hash or compare key numbers from the JSON sidecar; pinned to Task 10 Step 1 (CI drift check test asserts failure when a number is tampered).
