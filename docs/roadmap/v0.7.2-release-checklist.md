# v0.7.2 — the steps only a person takes

Prepared on 2026-10-13. `main` carries the release's work through pull requests #43, #44, #45
and #47; this file arrives with the commit that sets every version site to 0.7.2. Nothing has
been tagged or published.

**What the green does and does not prove.** Each pull request merged on a green `ci.yml` run
(fourteen jobs). Every local result is from one macOS machine. Each engine change was also
given to an independent reviewer that ran a differential probe against it, and each probe's
result is in the ledger row it belongs to. Not run by anyone: the publish rehearsal (below),
`claude plugin validate --strict` outside CI, and any test on Windows.

## Before anything leaves this machine

A tag freezes each of these. Each is in force on `main`; tick it to accept, or change it first.

- [ ] **D1 — this is 0.7.2 and not 0.8.0.** It refuses several inputs 0.7.1 accepted (D4) and
      reserves two words in the query language (D3). The other option is to call it 0.8.0.
- [ ] **D2 — two optional snapshot sections are added in a patch release**: a mark of how much
      WAL a keep-WAL snapshot holds (row 91) and a marker that the writer sweeps a deleted
      node's edges (row 95). The container version does not change, and the released 0.7.1
      wheel was shown opening snapshots that carry them. `docs/site/durability.md` promises
      only that the *version* moves on minor releases.
- [ ] **D3 — `true` and `false` are reserved words in the Cypher subset**: literals wherever a
      literal is read, and a parse error as a variable or an alias (row 63).
- [ ] **D4 — inputs now refused**: an `/algo/*` request with a field the config does not have
      (row 87); a PageRank damping outside 0 to 1 (row 75); a non-numeric `min`, `k` or `limit`
      to the MCP `find_similar` (row 74); a `remember` key, predicate or label of only
      invisible characters (row 78); a view named after a property nodes already carry, now
      refused before it is logged (row 95).
- [ ] **D5 — `was_linked` asks about the node that holds a key now.** A commit at which an
      earlier, since-deleted holder of the key was linked answers `false` (row 93).
      `node_history`, `edge_history` and `edges_at` are not bounded this way.
- [ ] **D6 — a store already unopenable is handled three ways.** Row 94's opens again with
      nothing lost. Row 95's leftover edges are dropped when 0.7.2 opens the store. Row 91's
      is not repaired: the changelog gives a manual step and says when not to use it.
- [ ] **D7 — row 92 ships as a known limit.** A crash between a truncating snapshot and the
      replacement of its WAL, after a rename, leaves a store that does not open. The fix needs
      the snapshot and its WAL to be swapped atomically and is deferred to 0.8.
- [ ] **D8 — a reopen of a store with a view over a rule-derived edge type is slower**, because
      the view is now kept right during replay: a reviewer measured 0.79 s to 1.97 s on a store
      with 396,000 derived edges and its snapshot at the halfway point.
- [ ] **D9 — rows 50, 51, 64 (half), 65, 88, 90 and 92 go to 0.8** with rows 83 to 85.
- [ ] **D10 — the index-persistence work (row 36, pull request #46) is not in this release.**
