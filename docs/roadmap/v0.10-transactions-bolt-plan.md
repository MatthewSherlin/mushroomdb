# W3 — Interactive Transactions and Bolt Wire Protocol Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver real BEGIN/COMMIT/ROLLBACK transactions across all four surfaces (Rust, Python, TypeScript, HTTP), move every HTTP read route to the lock-free reader, and implement the Bolt 4.4/5.0 wire protocol so official drivers connect with zero configuration change.

**Architecture:** An optimistic `Transaction` type buffers ops + a frozen `ReaderSnapshot` (no write lock held); `COMMIT` submits one `WalRecord::Batch` via `SharedDb::submit_batch_cas` with `NodeUnchangedSince` preconditions for every read/written node key, giving snapshot isolation. The Bolt crate is a new workspace-internal crate; its TCP listener reuses the server's rustls config. The procedure registry trait lives in `crates/core-query` so W1's Cypher executor can dispatch `CALL` without depending on `crates/bolt`.

**Tech Stack:** `tokio` (already in server), `rustls` (already in server), `rand` (already a direct dep), hand-written PackStream v1; crate `mushroomdb` (`core-api`), `mushroomdb-storage` (`core-storage`), `mushroomdb-query` (`core-query`), `mushroomdb-server` (`server`), `mushroomdb-cli` (`cli`).

**Spec:** `docs/roadmap/v0.10-spec.md` §4.2, §4.3, §4.5, §4.6 and `docs/roadmap/v0.10/W3-transactions-bolt.md`.

## Review Focus

These are the five failure classes most likely to reach users; each has a pinning test assigned to a task below.

1. **Crash mid-tx before WAL fsync** — if the error path does not drop the buffer cleanly, a retry could double-apply ops. Pinned in TX-1 (sim-harness crash-before-fsync differential probe).
2. **Stale `base_snap` when a snapshot fires during an open tx** — CAS preconds built from the base snapshot's `last_change` must still match what the drain thread sees even if a fold epoch advanced. Pinned in TX-1 (snapshot-fires-during-open-tx probe).
3. **Manifest indicator slot `0x000001FF` not skipped** — current Python and JS drivers put this slot in the handshake; a server that matches only exact version bytes will reject the connection before HELLO. Pinned in TX-9 (manifest-slot negotiation test, must pass before any driver test).
4. **`derived: false` on snapshot node-edges after delta tail has derived inserts** — ledger row 114. `node_edges_from` at `crates/core-api/src/reader.rs:851` hard-codes `derived: false`; the delta tail's `CommitDelta.derived_inserts` is never consulted. Pinned in TX-6.
5. **GIL held across `upsert_node` read-then-write** — ledger row 65. `upsert_node` at `bindings/python/src/lib.rs:215` calls `self.with_ref` then `self.with_mut` without `py.allow_threads`, blocking every other Python thread during WAL fsync. Pinned in TX-2 (concurrent-thread test).
