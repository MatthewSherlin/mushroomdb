# W2 — Types, Constraints, Range Indexes, Schema DDL, V11 Format Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Date/DateTime/Duration/Binary property types, unique constraints, range indexes, and Cypher schema DDL to mushroomdb 0.10, with V11 snapshot opt-in triggered at the first V11-type write.

**Architecture:** New `Value` variants (bincode discriminants 6–10) feed typed column storage, JSON wire forms, Python / TypeScript / Arrow bindings, and a unified equality+range index. The opt-in is a single choke point: `commit_logged_batch` (`crates/core-api/src/db.rs:6901`) detects the first V11-only record (a new-type value or a CreateConstraint / EnableRangeIndex WAL record) and writes a V11 snapshot before the WAL append, following the exact pattern of `enable_multiplicity()` / V10. `snapshot::version_for` takes a `StoreFeatures` struct in place of the bare `bool` and determines the snapshot version from all declared features.

**Tech Stack:** Rust; `time` 0.3 (approved; transitively present) for ISO 8601; `bincode` for WAL/snapshot META; `rkyv` for zero-copy snapshot sections; `serde_json` for JSON wire; `pyo3` for Python bindings; TypeScript client types; `criterion` for benchmarks.

**Spec:** `docs/roadmap/v0.10-spec.md` §4.1 + `docs/roadmap/v0.10/W2-types-constraints-indexes.md`

## Review Focus

Five input classes most likely to bite a real user that the default task tests miss. Each is pinned to a task.

1. **`DateTime` UTC-equality in unique constraint**: two nodes with the same UTC instant but different UTC offsets (`"T12:00:00+00:00"` vs `"T07:00:00-05:00"`) must produce `ConstraintViolation` because `DateTime` equality compares `micros_utc` only. Pinned to Task 5 step 1 (`test_unique_constraint_datetime_offset_equality`).
2. **`Binary` size boundary**: a write of exactly `BINARY_MAX_BYTES` (1 MiB = 1_048_576 bytes) succeeds; a write of `BINARY_MAX_BYTES + 1` returns `Err(GraphError::ValueTooLarge { ... })`. Pinned to Task 5 step 1 (`test_binary_size_limit`).
3. **Range predicate on a `Mixed` column**: when nodes have different types on the same field, the range index lookup returns only nodes whose type matches — no crash, no wrong results. Pinned to Task 10 step 1 (`test_range_predicate_mixed_column`).
4. **Drop constraint then re-create on the same `(label, field)`**: the backing equality index survives the drop; the second `CREATE CONSTRAINT` must not fail with a duplicate-index error. Pinned to Task 6 step 1 (`test_constraint_drop_and_recreate_same_field`).
5. **`open_at` before a constraint was declared returns empty `SHOW CONSTRAINTS`**: WAL replay stops at the target commit, so `CreateConstraint` records after it are not applied. Pinned to Task 7 step 1 (`test_open_at_before_constraint_declaration`).

## Cross-workstream Interfaces Produced

**For W1** (temporal Cypher functions — `date()`, `datetime()`, `duration()`):
- `Value::Date(i32)`, `Value::LocalDateTime(i64)`, `Value::DateTime { micros_utc: i64, offset_seconds: i16 }`, `Value::Duration { months: i32, days: i32, nanos: i64 }` in `crates/core-storage/src/types.rs`
- `ValueKey::DateDays(i32)`, `ValueKey::LocalDateTimeMicros(i64)`, `ValueKey::DateTimeMicrosUtc(i64)` in same file
- ISO 8601 helpers `date_to_iso8601`, `iso8601_to_date`, etc. in `crates/core-storage/src/types.rs`

**For W3** (PackStream encoding of new types; constraint check at transaction commit):
- Canonical internal representation (spec §3.1.11): `Date` → `i32` days; `LocalDateTime` → `i64` microseconds; `DateTime` → `(i64 micros_utc, i16 offset_seconds)`; `Duration` → `(i32 months, i32 days, i64 nanos)`; `Binary` → `Vec<u8>`
- Constraint checking is **automatic**: W3 transaction commits submit a `WalRecord::Batch` via `write_batch_cas` (`db.rs:13101`), which calls `commit_logged_batch` — the constraint check already runs there. W3 does not call a separate `check_constraints` function.

**For W5** (CSV import uses constraints):
- Same automatic enforcement: CSV import goes through `ingest_batch` / `commit_logged_batch`. Constraint violations on import rows produce `GraphError::ConstraintViolation`; the caller may choose to collect row-level errors.
