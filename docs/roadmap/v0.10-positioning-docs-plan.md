# W6 — Positioning, Public API, Docs, Integrations, Ledger Triage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reposition mushroomdb from an agent-memory tool to a general graph database for any app, while preserving the memory API in its own namespace, restructuring docs graph-first, and closing ten deferred ledger rows.
**Architecture:** All changes are docs/metadata/binding-surface: no engine, storage or query-engine code is touched (PS-11 is the sole Rust logic change — one function signature). The Python `db.memory.*` namespace is a thin Rust newtype holding a `Py<GraphDb>` ref; deprecated aliases delegate and emit `warnings.warn` via the Python C API. CLI reordering is a clap display-order annotation. The conformance table (PS-6) is generated from W1's tck-runner output and gated by CI.
**Tech Stack:** Rust (pyo3, clap), Python (pyo3 MemoryAccessor, pytest), mdBook (SUMMARY.md, book.toml), bash (gen scripts, CI), GitHub Actions YAML
**Spec:** `docs/roadmap/v0.10-spec.md` and `docs/roadmap/v0.10/W6-positioning-api-docs.md`

## Review Focus

Five failure modes the spec implies but no single task's tests exercise — each is pinned by a test in the task indicated:

1. **`DeprecationWarning` stacklevel wrong (PS-2):** `warnings.warn` from Rust via pyo3 must pass `stacklevel=2` (Python-level) so the warning filename points to the caller's `.py` file, not the pyo3 FFI frame. A test that checks `w.filename` catches this; a test that only checks `w.category` does not. Pinned in `test_deprecation_warning_reports_caller_frame` in PS-2.
2. **CLI stdin trailing newline garbles the query (PS-3):** reading from a file or stdin that ends with `\n` must strip the trailing newline before passing to the Cypher lexer, or the parser sees an unexpected end-of-input token. Pinned in `stdin_trailing_newline_is_stripped` in PS-3.
3. **Conformance table gate silent false-negative (PS-6):** `gen-conformance-table.sh` must exit non-zero when tck-runner produces empty output or is absent; a CI step that only checks the generated file's hash against the committed one would pass on an empty file if the committed one was also empty. Pinned in a bats/shell test in PS-6.
4. **`delivery_for_store` call-site breakage on row-69 fix (PS-10):** the public function `pub fn delivery_for_store(db_dir: &Path) -> Delivery` is called at `crates/cli/src/lib.rs:2136` and `:2228`. If the row-69 fix adds a `home: &Path` parameter, both call sites must be updated. A silent fallback to `Delivery::default()` would regress the bug silently. Pinned in `delivery_for_store_finds_user_scope_manifest_beside_home` in PS-10.
5. **`check-claims.sh` misses new subdirectory pages (PS-1):** the current glob `ls docs/site/*.md` does not recurse into `docs/site/get-started/` (added by PS-4). The scan must be changed to `find docs/site -name '*.md'` before PS-4 adds any pages. Pinned by running `check-claims.sh` in PS-1's test step after extending the glob.
