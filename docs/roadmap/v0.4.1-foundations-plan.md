# v0.4.1 Foundations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the rule engine's backfill safe at scale (kill the Cartesian-product memory wall) and close the CI/trust blind spots, then ship it as a **format-stable patch release (0.4.1)**.

**Architecture:** Two independent workstreams behind one release. (A) Bound rule backfill memory to `O(sources × max_edges)` by applying per-source top-k *before* pairs accumulate into the global desired-map, and by capping the `max_edges = None` global path. (B) Turn the repo's existing-but-`#[ignore]`'d recall tests and stale benchmark baselines into real CI gates, audit prod-path `unwrap`s, and add two fuzz targets. Neither touches the on-disk format.

**Tech Stack:** Rust (workspace of 9 crates), `cargo test`, `criterion` benches, `proptest` (already used), rkyv/bincode storage, PyO3 bindings, axum server.

**Spec:** This plan is self-contained. Background: `docs/site/durability.md`, `docs/site/roadmap-moat.md`, and the perf/quality findings summarized inline below.

## Global Constraints

- **Format stability (the reason this is a patch):** No change to the on-disk format is permitted in this release — no new WAL record discriminants, no snapshot section changes, no bincode field reorders. A 0.4.x store must open unchanged before and after. Verify with the existing snapshot round-trip tests.
- **No behavior change to derived edges:** the backfill fix must produce **byte-identical derived edges** to today (same top-k selection: score DESC, then dst key ASC). It is a memory/perf fix only.
- **TDD:** every code change starts with a failing test. The repo uses this discipline throughout; follow it.
- **Conventions:** match surrounding code style. Test-only instrumentation uses `#[cfg(test)]` static `AtomicUsize` counters (see the existing `SCAN_KEY_FIRES` / `INDEX_SCAN_FIRES` pattern in `crates/core-query/src/cypher/exec.rs`).
- **Commit cadence:** commit after each task. Conventional commits, lowercase (`fix:`, `perf:`, `test:`, `ci:`, `chore:`). Use the committer's own git identity.
- **Verify before done:** `cargo test --workspace`, `cargo clippy --workspace --all-targets`, `cargo fmt --check` must all be clean before the release task.

## Where 0.4.1 sits (context for the executor)

mushroomdb is at **v0.4.0** (property index, Cypher fluency, temporal `query_at`, trust hardening — all shipped). The strategy is now **foundations-first**: a series of small, format-stable **patch** releases (0.4.1, 0.4.2, …) that make the engine unshakeable, before the v0.5.0 feature minor (agent-memory: namespaces, bi-temporal, decay). Patch releases never change the format, so users on a 0.4.x line upgrade without a rebuild.

**0.4.1 is the highest-value patch** because it removes a wall that makes the flagship feature (declarative rules) blow up on real data: a real dogfood measurement projected a `70k × 20k` rule at **~685 min / ~331 GiB**. That is a correctness-of-scale defect, not slowness. This plan fixes it and hardens CI so future perf/recall regressions can't slip through silently (a gap the project has carried for three releases).

## Workstream A — Rule backfill scalability

### Task 1: Confirm the exact memory wall with a profiling test

**Files:**
- Test: `crates/core-rules/src/engine.rs` (inline `#[cfg(test)] mod tests`)

**Why:** Before changing hot code, prove *where* pairs accumulate. Two suspects: (1) the `max_edges = None` path accumulates the full cross-product before the global budget; (2) `compute_full_desired` extends the global desired-map with *un-truncated* per-source maps. Confirm both with an instrumented counter so the fix targets the real site.

**Interfaces:**
- Produces: a `#[cfg(test)] pub(crate) static PEAK_DESIRED_PAIRS: AtomicUsize` in `engine.rs`, incremented/max-tracked wherever the desired-map grows, so tests can assert the peak simultaneous pair count.

- [ ] **Step 1: Read the current flow.** Read `compute_desired` (~246), `compute_desired_via` (~452), `compute_full_desired` (~945), `filter_src_top_k` (~626), `edge_budget` (~599), and the `create_rule` backfill orchestration (~2027). Write down, in a comment in the test module, which function holds the largest map and whether `filter_src_top_k` is applied per-source *before* `compute_full_desired` extends the global map. This is analysis, not code.

- [ ] **Step 2: Add a test-only peak counter.** Near the top of `engine.rs`:

```rust
/// Test-only: the largest number of desired (src,dst) pairs held in memory at
/// once during a backfill sweep. Lets scale tests assert bounded materialization.
#[cfg(test)]
pub(crate) static PEAK_DESIRED_PAIRS: std::sync::atomic::AtomicUsize =
    std::sync::atomic::AtomicUsize::new(0);

#[cfg(test)]
pub(crate) fn record_desired_len(n: usize) {
    use std::sync::atomic::Ordering;
    let mut cur = PEAK_DESIRED_PAIRS.load(Ordering::Relaxed);
    while n > cur {
        match PEAK_DESIRED_PAIRS.compare_exchange_weak(cur, n, Ordering::Relaxed, Ordering::Relaxed) {
            Ok(_) => break,
            Err(actual) => cur = actual,
        }
    }
}
```

Call `record_desired_len(desired.len())` inside `compute_full_desired` after each `desired.extend(...)` (guarded by `#[cfg(test)]`), and also record the per-source map length inside `compute_desired` before it returns.

- [ ] **Step 3: Write the failing scale test.** Add to the `tests` module. Build a fixture where 400 source nodes and 400 destination nodes all share one `FieldEqual` value, with `max_edges = Some(5)`. Correct behavior: 400 × 5 = 2000 derived edges, and the peak simultaneous pairs should be bounded near `sources × k` (≈2000), NOT `sources × dsts` (160000).

```rust
#[test]
fn backfill_does_not_materialize_the_cross_product() {
    use std::sync::atomic::Ordering;
    // Build via the engine's public test harness (mirror an existing backfill
    // test such as `backfill_creates_edges_with_scores_and_delete_removes_exactly_them`).
    // 400 Person + 400 Org, all city="austin"; rule FieldEqual{city}, max_edges=Some(5).
    let (mut eng, mut g) = /* harness setup mirroring an existing backfill test */;
    for i in 0..400 { /* insert Person p{i} city=austin */ }
    for i in 0..400 { /* insert Org o{i} city=austin */ }
    PEAK_DESIRED_PAIRS.store(0, Ordering::Relaxed);
    eng.create_rule(field_equal_rule("Person","Org","city","IN_CITY", Some(5)), &mut g).unwrap();

    let edges = /* count derived IN_CITY edges */;
    assert_eq!(edges, 400 * 5, "per-source top-k must yield exactly k per source");
    let peak = PEAK_DESIRED_PAIRS.load(Ordering::Relaxed);
    assert!(
        peak <= 400 * 5 * 4, // generous headroom; NOT the 160_000 cross product
        "backfill must not materialize the full cross-product; peak was {peak}"
    );
}
```

If it *passes*, the accumulation is elsewhere — re-read Step 1's suspects and move the counter to the real accumulation site until the test fails for the right reason.

- [ ] **Step 5: Commit.** `git add crates/core-rules/src/engine.rs && git commit -m "test(rules): failing scale test pins backfill cross-product materialization"`

### Task 3: Cap the `max_edges = None` (global-budget) path

**Files:**
- Modify: `crates/core-rules/src/engine.rs` — the global-budget branch reached when `def.max_edges` is `None` (`edge_budget`, ~599, and its call sites).

**Why:** With `max_edges = None`, there is no per-source k, so today the full cross-product accumulates before the *global* `DEFAULT_MAX_EDGES` budget applies. Bound it by streaming: keep a global bounded max-heap of size `DEFAULT_MAX_EDGES` and never hold more than that plus one source's candidates.

**Interfaces:**
- Produces: for `max_edges = None`, peak pairs ≤ `DEFAULT_MAX_EDGES + max_per_source_candidates`, not the cross-product.

- [ ] **Step 1: Failing test.** Add a variant of the Task 1 test with `max_edges = None` and 400×400 shared value; assert the final edge count equals `min(cross_product, DEFAULT_MAX_EDGES)` **and** peak pairs stays bounded (≤ `DEFAULT_MAX_EDGES + 400 * 4`). Run — expect FAIL on the peak assertion.

```rust

    // Same 400x400 shared-value fixture, but FieldEqual rule with max_edges = None.
    // Assert: final edges == min(160_000, DEFAULT_MAX_EDGES);
    //         PEAK_DESIRED_PAIRS <= DEFAULT_MAX_EDGES + 400 * 4.

```

- [ ] **Step 2: Stream into a bounded global heap.** Replace the "accumulate-all-then-truncate" global path with a `std::collections::BinaryHeap` (min-heap by score via `Reverse`) of capacity `DEFAULT_MAX_EDGES`. Preserve the exact final selection (score DESC, dst-key ASC) — sort the heap's contents once at the end with the same comparator used in `filter_src_top_k`.
