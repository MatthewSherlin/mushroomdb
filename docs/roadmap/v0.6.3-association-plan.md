# v0.6.3 — the association release: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure the engine on association, retraction, time-travel and visibility questions against files+grep and SQLite, with the graph as the agent's only data path in its arm; run the three no-choice code-door arms alongside; ship 0.6.3 with both gate tables as measured.

**Architecture:** One deterministic world generator writes three forms (JSON files, SQLite, a mushroomdb store with rules, a replayed changelog and roles). An engine-independent truth script grades against brute-force rule evaluation and is cross-checked against the engine. The harness gains a suite switch and a parameterised gate. The MCP server gains an association surface (memory stores list association tools, not code tools), a text-first `explain_association`, and a `role` argument on `query`. Two new install flags deliver graph facts through hooks without a tool call.

**Tech Stack:** Rust 1.92 workspace (hand-rolled arg parsing, serde_json, pyo3 binding), Python 3.11 harness with pytest (`bindings/python/.venv/bin/python`), `sqlite3` 3.43 on PATH, Claude Code 2.1.x (`claude -p`).

**Spec:** `docs/roadmap/v0.6.3-association-spec.md`.

## Global Constraints

- Ships as **0.6.3**. The association surface replaces the memory-store default listing (breaking for programmatic callers relying on the old listing; CHANGELOG says so).
- **No on-disk format change.** New Python binding methods are wrappers over existing engine APIs.
- **Nothing committed names or compares against other products.** SQLite is a baseline, not a competitor; FastAPI stays as the 0.6.2 subject.
- **"Time" is a commit index.** The store carries no wall clock; the builder records `day → commit` itself. The builder never snapshots the store after applying the changelog (snapshot retention would cut the WAL horizon that `was_linked`/`query_at` need).
- Truth is computed twice (independent Python, engine); a task whose truths disagree is dropped and filed.
- Prompts never mention mushroomdb; every form's `README.md` describes the rules in identical prose.
- Skill template and every rendered variant ≤ 6,000 bytes; cursor rules ≤ 60 lines; hook budgets: PreToolUse/PostToolUse new hooks timeout 5 s, no `async`; injected context ≤ 600 B (impact) / ≤ 800 B (grep enrichment).
- Hook JSON on stdout (`hookSpecificOutput`) is new to this repository: the implementer confirms key names against the Claude Code hooks reference before writing them and pins the emitted shape with a fixture test.
- TDD; conventional lowercase commit subjects; no commit trailers (`git -c commit.gpgsign=false commit -m "<subject>"`).
- The harness never runs from a dirty subject; every cell records its own stream; numbers in docs only from committed `summary.md`.
- Benchmark cells cost plan usage (API-equivalent estimates): the association run ≤ $40, the code-door run ≤ $60; stop and report past those.

### Task 3: The world builder — one generator, three forms

**Files:** Create `benchmarks/agent-tasks/association/{__init__.py,build.py,README.tmpl.md}`; modify `test_agent_harness.py`.
