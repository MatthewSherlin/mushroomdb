# v0.8.2 — the steps only a person takes

Prepared on 2026-10-16. `main` carries the release's work through pull requests #64 and #65; this
file arrives with the commit that sets every version site to 0.8.2. Nothing has been tagged or
published.

**What the green does and does not prove.** Each pull request merged on a green `ci.yml` run
(seventeen jobs). Every local result is from one macOS machine. Both changes were given to an
independent reviewer that ran a differential fuzz and measured the cost against `main`; the row 107
review also opened stores written by the real 0.8.0 release, one of which is now a test fixture.
Not run by anyone: the test suite on Windows.

## Before anything leaves this machine

A tag freezes each of these. Each is in force on `main`; tick it to accept, or change it first.

- [ ] **D1 — this is 0.8.2, a patch release.** No format version change; 0.8.1 and 0.8.0 open a
      0.8.2 snapshot and count its edges right.
- [ ] **D2 — the repair runs at the first write after open, not at open.** Until then `stats().rules`,
      `explain` and `open_at` on a damaged store still show two owners for an edge.
- [ ] **D3 — row 111 ships as a known limit.** A store where 0.8.0 had already lost an edge is not
      repaired; delete and recreate both rules. The changelog says so.
- [ ] **D4 — measured costs.** The first write after open on a store with 1M derived edges is about
      70 ms (5 %) slower, for the repair pass. A write to a destination with 50,000 incoming
      edges beside a via-hop top-k rule that never matches it: 34 ms on 0.8.1, 61 ms now; its
      delete 133 ms and 165 ms.
- [ ] **D5 — deferred to 0.8.3:** rows 50, 84 (the `rebuild_rule` half), 101, 102, 108–111 and the
      Low rows.
- [ ] **D6 — the `core_api` → `mushroomdb` library rename is not in this release.**
