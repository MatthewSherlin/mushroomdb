# v0.6.x — the proof series: design

> **Closed 2026-09-11 (v0.6.4).** Its §1 gate (correctness ≥ stock, cost ≤ stock, adoption ≥ 80%,
> no max-turns regression) was evaluated in full and **failed on every arm**, with the §1
> consequence applied as written: the code-graph door stops receiving investment. Phases 2 and 3
> were never started. Evidence: `results/20260910T000418Z`, `results/20260910T050239Z`.

**Date:** 2026-09-09
**Status:** draft for owner review
**Owner decision it implements (2026-09-09):** improve the code-graph door and prove it
against a stock coding-agent harness before any internal wrapper ships it.

## 1. Goal and the gate

The code-graph door (`npx mushroomdb install` → skill + MCP + hooks) must measurably beat a
stock Claude Code session on long-horizon repository tasks before it is rolled out to a fleet.
Today it does not: on the 10-question harness the invoked arm costs +54% tokens versus stock,
scores 0.898 versus 0.955, and is adopted in 65% of invoked sessions and 10% of installed
ones (`benchmarks/agent-tasks/results/20260909T120726Z`).

**Gate (pre-registered, evaluated on harness v2, §3):** the best graph arm, across all three
reps and both repositories,

1. correctness ≥ stock (mean graded score, paired by task),
2. cost ≤ stock (mean USD per cell, Sonnet pricing at run time),
3. adoption ≥ 80% of sessions make at least one graph call (tool or CLI),
4. no cell fails on `max-turns` where stock succeeds.

If phases 1 and 2 (§4, §5) do not reach the gate, the code-graph door stops receiving
investment; the engine and the memory door continue. That outcome is recorded as a result,
not hidden.

## 2. What we learned that shapes the design

- **MCP schemas are deferred by the host.** Claude Code 2.1.258 lists `ToolSearch` and loads
  MCP tool schemas on demand. The 0.6.1 harness sessions called `ToolSearch` twice before their
  first graph call. Every MCP-delivered session pays discovery turns; the byte size of
  `tools/list` matters less than the number and discoverability of tools. Two delivery paths pay
  no discovery cost: context injected by hooks, and plain CLI commands through `Bash`.
- **Per-prompt injection defeats prompt caching.** The `UserPromptSubmit` recall block changes
  every turn. Stable, session-start content is cached; churn is paid on every request.
- **Small tasks cannot show a graph win.** Two-to-four-turn lookups are answered by `grep`
  faster than any tool can be discovered. The benchmark must contain tasks where a stock agent
  spends many turns exploring.
- **Bodies cost more than pointers.** `context` returns 3–4 KB per call. The host already has
  `Read`; the graph's job is to locate, not to deliver source.

## 3. Phase 0 — harness v2

Lives in `benchmarks/agent-tasks/` (untracked today; v2 is committed under
`benchmarks/agent-tasks/` with results directories git-ignored except `summary*.md`).

### 3.1 Repositories

- **R1:** this repository at the run's HEAD (Rust, ~430 files).
- **R2:** one public, permissively licensed Python or TypeScript repository with 300–800
  source files and a test suite that completes in under five minutes on a laptop. Default
  candidate: FastAPI (MIT, Python, pytest); the implementer verifies file count, test time and
  extractor coverage (`mushroomdb ingest-git` reports symbols and calls > 0 for ≥ 90% of source
  files) before pinning a commit SHA in `tasks.json`. R2 is cloned per run at that SHA.

### 3.2 Task kinds (10 tasks per repo, 20 total)

| Kind | Count | Ground truth | Example shape |
|---|---|---|---|
| Change-and-pass | 3 | Executable: named tests pass after the agent's edit, and the diff touches every file in the truth set | "Rename `X` to `Y` everywhere it is used and keep tests green" |
| Blast radius | 2 | File set from the call graph at the pinned SHA, hand-verified | "Which files need attention if `fn f` changes signature?" |
| Localize from symptom | 2 | File and function | "Requests with an empty header panic. Where?" (symptom written from a real commit's bug) |
| Navigation | 2 | File and line | "Where is the retry policy configured, and which function reads it?" |
| History and ownership | 1 | Git-derived list | "Who owns `path`, and which files change with it?" |

Rules: every task takes a stock Sonnet agent at least 6 turns in a pilot run (a task that
stock answers in ≤ 4 turns is replaced); prompts never mention mushroomdb; the truth for
task 7's blast-radius kind excludes same-named fixture symbols (the 0.6.1 grader defect).

### 3.3 Arms

| Arm | Install | Prompt | Delivery |
|---|---|---|---|
| A stock | none | plain | — |
| B installed | `install --project` | plain | MCP + skill + hooks |
| C invoked | same as B | `/mushroom ` prefix | MCP + skill + hooks |
| D cli | `install --project --delivery cli` (§4.5) | plain | skill teaches `mushroomdb …` via `Bash`, no MCP server |

Per-cell: `claude -p`, `--max-turns 30`, cell timeout 900 s, allowed tools
`Read,Grep,Glob,Bash,Edit,Write` plus `mcp__mushroomdb` for B and C. Change-and-pass cells run
in a fresh worktree per cell; tests run after the agent exits. 3 reps × 4 arms × 20 tasks = 240
cells; pilot budget ≤ $40 per full run.

### 3.4 Metrics per cell

score, total tokens, input, output, cache_read, cache_create, **cache-hit ratio** =
cache_read / (cache_read + cache_create + input), cost USD, turns, tool calls, graph calls
(MCP tool calls + `Bash` invocations of `mushroomdb`), `ToolSearch` calls, adoption (graph
calls ≥ 1), outcome (success / max-turns / timeout / error), wall-clock (reported, never quoted).

`summary.md` reports per-arm means, paired deltas versus A with 95% bootstrap intervals, the
gate verdict, and one line per sub-1.0 cell classified `tool | model | grader`.

### 3.5 Harness changes

`run.py`: arm D, `--delivery`, `--max-turns`, per-cell worktree + post-run test command from
`tasks.json`, R2 clone at SHA, cache-hit ratio, ToolSearch count, bootstrap intervals.
`ground_truth.py`: R2 support, executable truth, fixture exclusion. `rescore.py` unchanged in
spirit. Tests: `benchmarks/test_harness.py` covers the new metrics and the gate verdict.

## 4. Phase 1 — delivery mechanics

All changes are additive to the CLI (`crates/cli`), the MCP server (`crates/server`), the
skill (`crates/cli/skills/mushroom/SKILL.md`) and the plugin templates. No engine format
change. Each item is re-measured on harness v2 before the next starts.

### 4.1 Session brief (SessionStart hook)

`mushroomdb brief --auto` prints ≤ 1,000 tokens: one status line (store, nodes, edges, last
sync SHA), the top 25 files and top 25 symbols by PageRank from the existing `map`
computation (path and one-line role), and one line naming how to reach the graph in this
session (`explore` tool, or `mushroomdb explore` on the CLI arm). Output is a pure function of
the store's commit sequence, so it is byte-identical across prompts in a session and cached by
the host. `install` registers it under `hooks.SessionStart`; `doctor` checks it; `enable` /
`disable` toggle it with the others.

### 4.2 Recall becomes precise

`recall --auto` keeps its silence rule and adds: it prints only when the prompt names a symbol
or path that resolves in the graph (exact or BM25 hit above the existing floor), and the reply
is ≤ 300 tokens of pointers (`path:line symbol — one line`). No map, no prose. The nudge text
is dropped; the brief already told the agent how to reach the graph.

### 4.3 Pointers, not bodies

`context`, `impact`, `why`, `owners`, `map` render `path:start-end symbol — first doc line`
plus a signature of at most three lines per hit. A `full: true` input (MCP) / `--full` (CLI)
restores today's bodies. Budget: a default `context` reply ≤ 1,200 tokens on this repository.

### 4.4 One tool to find

Default MCP surface becomes three tools: `explore`, `query`, `stats`. `explore(target, depth,
budget)`: `target` is a symbol, path or free text; `depth` ∈ `context | impact | history | all`
(context = definition + callers + callees; impact = blast radius; history = owners + co-change
+ why); `budget` caps reply tokens (default 1,200). Its description is written for discovery
under deferred loading: it names call graph, callers, blast radius, ownership, co-change and
"why are these related" in the first sentence. `mushroomdb mcp --all-tools` still exposes
everything, and the individual task tools stay callable there. The server picks the default
surface from the store it opens: a store carrying the `GitSync` marker node (a repository was
ingested) gets the three-tool code-graph surface; any other store keeps today's eleven-tool
memory surface. No install flag decides this, so one `.mcp.json` serves both doors.

### 4.5 CLI delivery

`install --delivery cli|mcp|both` (default `both`). `cli` writes the skill variant that teaches
`mushroomdb explore <target> [--depth] [--full]` and `mushroomdb query` through `Bash`, writes
no MCP entry, and keeps the hooks. The binary path in the skill is the one `install` resolved
(§7.1 makes that path portable). The skill variant is rendered from the same source with a
delivery switch so the two never drift.

### 4.6 Grep redirect (experimental, off by default)

`install --intercept-grep` adds a `PreToolUse` hook (matcher `Grep`) running
`mushroomdb intercept --auto`: when the pattern is a single identifier that resolves to ≥ 1
symbol in the graph, exit 2 with a one-line message pointing at `explore`; otherwise exit 0.
Never matches `Read`, `Edit`, or `Bash`. Measured as arm variants B+ and D+.

## 5. Phase 2 — retrieval quality

Starts only after §4 is measured.

- **5.1 Identifier-aware lexical search.** The BM25 tokenizer splits `camelCase`,
  `snake_case` and path separators and indexes the pieces alongside the whole identifier, so
  "retry policy" finds `RetryPolicy` and `retry_policy_for`. Engine change in the fulltext
  tokenizer; format-stable (the index is rebuilt on open when the tokenizer version differs).
- **5.2 Static embeddings (opt-in).** `mushroomdb embed --auto` computes a vector per symbol
  and file from a small static-embedding table shipped as a separate download
  (`~/.mushroomdb/models/<name>`, verified by SHA256, never fetched by install). `explore` and
  `recall` use the existing hybrid (RRF) search when vectors exist and lexical search
  otherwise. Measured as arm variants; kept only if it moves correctness.
- **5.3 Co-change cap.** Co-change partners render the top 5 with counts, not the top 2.

## 6. Phase 3 — engine-native experiments

Each is a separate, flag-gated feature measured on harness v2; none ships on by default
before it wins.

- **6.1 Stale-read detection.** A `PostToolUse` hook on `Read` runs `mushroomdb saw --auto
  <path>` which records `(session, file, blob hash, time)` as a `Session` node and a `READ`
  edge. The existing edit and git hooks keep `File` hashes current. The brief and recall add a
  block "changed since you read: `path` (your edit | commit `sha`)" and suppress pointers to
  files read this session and unchanged. Measures: re-read rate, stale-edit rate, tokens.
- **6.2 Rule-derived relevance frontier.** A shipped rule derives `LIKELY_RELEVANT`
  (`Session` → `File`) from `READ` joined with `CALLS` and `CO_CHANGED`, retracting as reads
  and commits change. Recall injects the frontier's top 5 as "next files". Measures: turns to
  first correct file, tokens.
- **6.3 Later, after the series:** graph-backed compaction; a shared graph with masks for parallel
  subagents.

## 7. Phase 4 — fleet readiness (before any wrapper)

- **7.1 Committed config carries no machine path.** Project-scope `.mcp.json` and
  `.claude/settings.json` hold a portable command (`npx -y mushroomdb@<ver>` or bare
  `mushroomdb`); the resolved native-binary path goes to `.claude/settings.local.json` (hooks)
  and a `~/.mushroomdb/bin/<ver>` shim used by the portable command, so the 8 ms hook path
  survives without leaking a per-machine path into git. `doctor` reports which form is active.
- **7.2 Submodules.** `--auto` inside a submodule resolves to the enclosing superproject's
  store when that store has a sync key for the submodule; otherwise to the submodule's own.
- **7.3 `core.hooksPath`.** `install`, `doctor`, `enable`, `disable` honour it.
- **7.4 `enable`/`disable` default platform** = the platforms recorded in the manifest, never
  auto-detection.
- **7.5 Usage log.** `--usage-log` (or `MUSHROOMDB_USAGE_LOG=1`) appends one NDJSON line per
  hook and tool call to `~/.mushroomdb/usage.log`: `ts, session, kind (tool|hook|cli), name,
  duration_ms, reply_bytes, store_commit`. Never arguments, paths, or prompt text. Rotates at
  10 MB, keeps 3. `mushroomdb report` summarises a date range. Off by default.

## 8. Non-goals for the 0.6.x series

The internal wrapper PR, any hosted or multi-user mode, Windows, LongMemEval, new languages
in the extractor, and any change to the on-disk format.

## 9. Testing and verification

TDD per crate convention (`crates/cli/tests/*.rs` temp-HOME fixtures for install/hooks;
`crates/server` MCP tests for `explore` and pointer rendering; engine tests for the tokenizer).
`scripts/acceptance-0.6.sh` gains checks for the brief's token budget, `explore` reply budget
and hook latency. Harness v2 runs are recorded under `benchmarks/agent-tasks/results/<stamp>/`
with `summary.md` committed. No number is quoted in docs, README or CHANGELOG unless it comes
from a committed harness summary with the gate section.

## 10. Sequencing and release

Ships as patch releases on the 0.6 line, one per phase that lands: 0.6.2 = harness v2 + delivery mechanics (§3, §4); 0.6.3 = retrieval quality (§5) if the gate needs it; 0.6.4 = engine-native experiments (§6) that win; 0.6.5 = fleet readiness (§7). Order inside 0.6.2: Phase 0 → 4.1 → 4.2 → 4.3 → 4.4 → 4.5 (measure after each; 4.6 as a variant) → gate check →
Phase 2 only if needed for the gate → Phase 3 experiments → Phase 4. Each CHANGELOG entry carries the harness v2 table for what it changed; the 0.6.2 entry carries the gate verdict. The default MCP surface change in 0.6.2 is called out as breaking for programmatic callers, as the 0.6.1 text-only change was.
