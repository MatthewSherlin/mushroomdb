# v0.8.0 — the steps only a person takes

Prepared on 2026-10-14. `main` carries the release's work through pull requests #46, #49, #50,
#51, #52, #53 and #54; this file arrives with the commit that sets every version site to 0.8.0.
Nothing has been tagged or published.

**What the green does and does not prove.** Each pull request merged on a green `ci.yml` run
(seventeen jobs, three of them new per-target builds). Every local result is from one macOS
machine. Each engine change was also given to an independent reviewer that ran a differential
probe against it, and each probe's result is in the ledger row it belongs to. Not run by
anyone: the publish rehearsal (below), the release workflow's six-target packing and upload,
`npx mushroomdb` from the registry on a real Windows machine, and the test suite on Windows.

## Before anything leaves this machine

A tag freezes each of these. Each is in force on `main`; tick it to accept, or change it first.

- [ ] **D1 — this is 0.8.0.** The changelog records no input that 0.7.2's engine, CLI or
      server accepted and 0.8.0 refuses (the TypeScript client now refuses the keys `.` and `..`,
      which it could not address correctly), and the snapshot format version does not change; the minor version moves for the new platforms, the new client
      surface and the automatic snapshots.
- [ ] **D2 — a snapshot now carries the full-text index** as an optional section (row 36). The
      container version does not change; 0.7.2 opens such a snapshot, ignores the index and
      builds its own. The snapshot grows by the index, about a third on the store measured.
- [ ] **D3 — a snapshot that replaces the WAL writes `snapshot.intent` first** and empties it
      when done (row 92). A backup carries the file. 0.7.2 does not read it, so a store left by
      a crash in that window and then opened by 0.7.2 is in the state row 92 describes.
- [ ] **D4 — `mushroomdb mcp` snapshots on its own** when it opens a store whose WAL is past
      4 MiB, and again when its session ends. Each snapshot archives the WAL, so the store
      directory gains a `wal.<N>.archive` per snapshot. `MUSHROOMDB_NO_AUTO_SNAPSHOT=1` turns it
      off; `mushroomdb doctor` sets it on the server it starts.
- [ ] **D5 — six release targets.** Intel macOS, x86_64 musl Linux and x86_64 Windows join
      Apple Silicon and the two glibc Linux targets. Wheels stay at three targets. On Windows
      only the binary and the launcher are supported: `mushroomdb install` and its hooks are not.
      The npm package's `os` list now includes `win32`.
- [ ] **D6 — stores already damaged are not repaired.** An archive overwritten by row 100 is
      gone; a store that lost its genesis marker to row 98 keeps refusing reads by commit into
      its archives. The changelog says both.
- [ ] **D7 — the TypeScript client's `watch()` resolves `close()` within 3 s** against a server
      older than 0.8, which never answers a close on `/watch` (row 99).
- [ ] **D8 — 22 deferred rows go to 0.8.1**, among them 50, 51, 65, 83 to 85, 88, 90 and 101.
- [ ] **D9 — the 1M-node scale run and the `core_api` → `mushroomdb` library rename are not in
      this release.**

Then:

- [ ] Read `CHANGELOG.md`'s 0.8.0 section top to bottom.
- [ ] **The publish rehearsal. Not run**: the machine this was prepared on had about 10 GiB
