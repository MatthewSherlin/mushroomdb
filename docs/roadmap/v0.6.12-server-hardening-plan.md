# v0.6.12 — server hardening

**Source.** The v0.6.11 spec's non-goals (`docs/roadmap/v0.6.11-time-and-vectors-spec.md:224-234`)
named four HTTP-server defects and deferred them together, with a stated reason:

> These are real and they are **0.6.12**. This release changes the engine, and
> mixing a security-shaped server patch into a release that moves the vector
> format makes both harder to review.

0.6.12 was then the only named release with no document. This is that document,
written alongside the tasks rather than before them, which is a deviation from
the project's own convention and is recorded as one.

**All four tasks are now done.** Tasks 1 and 2 landed first; tasks 3 and 4
followed once the owner chose the additive API shape for shutdown.

---

## 1. The four, as the 0.6.11 spec named them

| # | Defect | Where |
|---|---|---|
| 1 | Unauthenticated `GET /health` returns `nodes` and `edges` while `/metrics` refuses a role-bound token because "counters leak graph size" | `http.rs:471`, `:433-446`, `:1060` |
| 2 | No request timeout, rate limit or concurrency limit anywhere; `tower-http` pulled with `fs` only | `crates/server/Cargo.toml` |
| 3 | SIGTERM does `serve.abort()`, killing in-flight requests and subscribers before snapshotting | `crates/cli/src/main.rs:734` |
| 4 | No `tracing`, `log`, access log or request id in the tree | — |

## 2. Task 1 — `/health` discloses liveness, not shape. **DONE**

The contradiction was exact: an **unauthenticated** caller read `nodes_live`,
`edges` and the bind address from `/health`, while an **authenticated**
role-bound token was refused the same counters by `/stats` and `/metrics` on the
stated grounds that counters leak graph size. One disclosure, two opposite
policies, and the unauthenticated side was the generous one.

**Shipped.** A third identity, `AuthIdentity::Anonymous`, for a caller that
reached an endpoint open by design without presenting a token that resolves to
anything. `/health` stays reachable without a credential — a load balancer has
none — and answers `{"ok": true}` and nothing else unless the caller holds the
full-access token.

Unchanged: a server with no auth configured at all still reports counts, because
there is no boundary to leak across. `/health` still answers 200 for everyone,
so no probe breaks.

**Tests.** `health_is_reachable_without_a_token_and_discloses_nothing`,
`health_reports_counts_to_a_full_token`,
`health_discloses_nothing_to_a_role_token`, and the pre-existing
`health_reports_counts` for the no-auth case. The first replaces
`health_is_unauthenticated`, which asserted the old contract.

**Note.** Adding the enum variant made the compiler name the one other match on
`AuthIdentity`. It is on a route `Anonymous` cannot reach, and it is now written
to refuse rather than to fall through to full access — an open endpoint added
later cannot inherit access by omission.

## 3. Task 2 — a deadline and a ceiling. **DONE**

Before this the only backstop was a 64 MiB body cap. A handler that never
finished held its connection, its permit and its read guard indefinitely, and
nothing bounded how many could do so at once.

**Shipped.**

- `TimeoutLayer` at **120 s**, answering `408 Request Timeout`. Sized for the
  slowest legitimate handler rather than the typical one — a `/query` over a
  large store, a `/backup`, a `/suggest` that profiles the graph. The point is
  not to make slow requests fast; it is that a request which will never finish
  stops holding resources forever.
- `ConcurrencyLimitLayer` at **256**, behind `LoadShedLayer`, answering
  `503 Service Unavailable`. It **sheds rather than queues**: an unbounded queue
  in front of a single-writer engine turns overload into latency that never
  recovers, and 503 is both the honest answer and the one a load balancer can
  act on. Load shedding surfaces as a `BoxError`, so it is mapped to a response
  by `HandleErrorLayer` — a Router's stack must be infallible.

**The WebSocket routes are exempt.** `/watch` and `/subscribe` are built as a
separate router and merged unlayered. A request timeout applied to them would
sever a healthy subscription at the deadline, and a subscription is meant to
outlive any request.

**Not done: a rate limit.** Deliberately. A per-client limit needs a keyed store
and a definition of "client", and behind a reverse proxy every request arrives
from the same peer address — so the obvious implementation limits the proxy, not
the caller, and the useful one requires trusting a forwarded header, which is a
policy decision about deployment rather than a default. The concurrency ceiling
bounds the resource that actually runs out.

## 4. Task 3 — graceful shutdown. **DONE — additive, by owner decision**

`crates/cli/src/main.rs:734` calls `serve.abort()` on SIGTERM, which drops
in-flight requests and live subscribers mid-response before the shutdown
snapshot runs. No data is lost — the WAL holds every commit and the next open
replays it, which the code comment already says — but a rolling restart severs
responses it did not need to.

The fix is `axum::serve(...).with_graceful_shutdown(...)`, and the signal has to
reach *inside* `serve_inner`. `mushroomdb-server` is a published crate with
**five** serve call sites across four public entrypoints plus a TLS path on
`axum_server::Handle`, so this is a public-API change either way:

- **(a) Additive.** Four new `*_with_shutdown` entrypoints; the existing four
  delegate with `std::future::pending()`. Non-breaking, and leaves eight public
  functions where four would do.
- **(b) Breaking.** Add the parameter to the existing four. The README already
  states *"Pre-1.0 alpha — APIs and formats may change between minor
  versions"*, so it is within the stated contract, and it keeps the surface
  honest — but it breaks anyone embedding the server.

**Owner decision, 2026-09-29: additive (a).** Five new entry points carry the
signal, each taking a `oneshot::Receiver<()>` that stops the server when it
fires *or is dropped*. The existing ones are untouched in signature and in
behaviour. The TLS path bridges onto `axum_server::Handle` with a 30-second
grace, because an unbounded grace lets one stuck request hold a restart open
forever.

`a_graceful_shutdown_drains_instead_of_severing` (`tests/e2e.rs`, over a real
socket) asserts the server exits cleanly on the signal and that the listener is
genuinely closed afterwards. An abort fails it: a cancelled task is not
`Ok(Ok(()))`.

## 5. Task 4 — tracing, access log, request id. **DONE**

There was no `tracing`, no access log and no request id anywhere in the tree,
so a 500 in production could not be tied to the request that caused it.

**Shipped, and the policy is the point.** A line per request at one level is
what makes a server log unreadable — the 200s bury the 500s, and nobody reads
it after the first week. The level follows the outcome:

| Outcome | Level | On by default |
|---|---|---|
| 5xx | `error` | yes |
| slower than 5s | `warn` | yes — the request heading for a timeout |
| 4xx | `info` | yes |
| everything else | `debug` | no |

Measured on the built binary: **twenty successful requests write nothing**; one
404 writes one line. Every response carries `x-request-id`, echoed from the
caller's header when present. The query string is never logged — it can carry
`?token=`.

`MUSHROOMDB_LOG` overrides the default. The subscriber is installed by the
binary, not the library: a library that configures global logging takes the
decision away from its embedder.

**One trap, pinned by a test.** The filter targets are the *lib* names —
`server` and `cli` — not the package names. The first version of this default
named `mushroomdb_server`, matched nothing, and looked exactly like a healthy
quiet server: a 404 logged at INFO and appeared nowhere.
`default_filter_names_the_servers_real_log_target` checks the filter against
`server::LOG_TARGET_ROOT`, which is `module_path!()`, so renaming the lib fails
the test rather than silencing the log.

## 6. What this patch changes for an existing caller

- **Shutdown drains.** SIGTERM lets in-flight requests and subscribers finish
  instead of severing them. An operator relying on the old abrupt stop sees a
  restart take as long as its slowest in-flight request (TLS: capped at 30s).
- **The server logs.** To stderr, quiet by default; `MUSHROOMDB_LOG` controls
  it. Anything parsing stderr as silence will now see lines on 4xx/5xx/slow.
- An unauthenticated or role-bound `GET /health` no longer carries `nodes`,
  `edges` or `addr`. Anything scraping those from an unauthenticated probe must
  present the full token or read `/metrics`. Liveness checks are unaffected.
- A request taking longer than 120 s now ends in `408` instead of hanging.
- Beyond 256 concurrent non-streaming requests the server answers `503` instead
  of queueing without limit.
- Nothing about the engine, the store format or the MCP surface changes.
