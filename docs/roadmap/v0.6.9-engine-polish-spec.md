## 1. Goal

When it ships:

1. **`n.id` / `id(n)` read the node key**, with the same stored-property-wins
   rule as `n.key` / `key(n)`. `WHERE n.id = 'alice'` on a node that has no
   stored `id` property returns the node. Pattern `{id:}` is already a key
   lookup and stays that.
2. **`WHERE` identity equality is O(1) when it can be.** `WHERE n.key` /
   `n.id` / `key(n)` / `id(n)` against a literal or `$param` uses `ScanKey`
   (plus a stored-prop filter so stored-wins still holds), not a label scan.
3. **Write-statement `RETURN` evaluates `CASE` and list subscripts**, and
   identity fields, the same way a read `RETURN` does.
4. **Python `upsert_node` is one WAL commit** via `GraphDb::set_props`.
   Python `query_at` takes `role=` / `namespace=` like live `query`.
5. **Kernel speed with no recall change:** reuse the HNSW `beam_search`
   visited bitset and heaps; reuse the query `f32` buffer; skip a second L2
   in GEMM `pack` when the vector is already unit.
6. **HTTP neighborhood absent-key is 404.** `POST /find_similar` exists.
   MCP lists **`pairwise_similar`** (association listing becomes 16).
7. **`degree(..., multiplicity=true)`** sums a persisted per-pair insert
   count. Default `degree` stays unique-neighbour. CSR stays a set. No V9.
8. **Unscoped MCP `stats` omits the namespace roster.** Pass `role` or
   `namespace` to see names.
9. **Parked / refused HNSW state survives reopen** inside the MHNS blob
   (blob v4, snapshot **V9 unchanged**).
10. **Recall sanitises bidi/ZW/line separators; Commit digest includes
    `message`; ingest-git summary splits delete vs rename-eviction.**
    `masks.md` and `service.md` enter `llms-full.txt`.

No HNSW parameter change. No recall floor is lowered. Snapshot format stays
**V9**. `roles.json` stays at the version 0.6.6 shipped (v4). Product-facing
docs name no competing database product and quote no sidecar wall-clock.

## 5. Contracts

### 5.1 Identity: `n.id` / `id(n)`

Extend `is_identity_field` / `node_identity_prop` so `id` is the third
identity name, alias of `key`:

- Stored property of that name **always wins**.
- Else `n.id` / `id(n)` return the id-map key string, same as `n.key` /
  `key(n)`.
- `id(n)` is a one-argument function, same errors as `key(n)` for a non-node.
- Pattern `{id: 'alice'}` is **not** this: it remains `ScanKey` (key selector
  on MATCH/MERGE/CREATE). CREATE may still stamp a stored `id` property; that
  node then reads `n.id` from the store, which equals the key.

Pin:

- `n_id_falls_back_to_key_when_unstored` — `insert_node` without `id` prop;
  `WHERE n.id = $k` and `RETURN n.id, id(n)` equal `n.key` / `key(n)`.
- `stored_id_property_wins_over_key` — node key `k`, stored `id` = `other`;
  `n.id` is `other`; `WHERE n.id = 'k'` does not match.
- `id_function_rejects_non_node` — named error, same class as `key()`.

Docs: rewrite the key-idiom section of `docs/site/query.md`. Delete
“WRONG: n.id is always null”. Keep stored-wins. Fix the Python README line
that still claims `n.key` does not resolve.

### 5.2 Identity equality → `ScanKey`

`fold_where_equalities` today folds `n.field = lit` to `IndexScan`. Identity
fields are not indexed that way, so `WHERE n.key = 'x'` scans the label.

New plan op or a tagged `IndexScan` mode **`IdentityEq { var, field, value }`**
for `field ∈ {key, id}` and `key(n)` / `id(n)` equality against `Lit`/`Param`:

1. Resolve `value`.
2. `ScanKey` that string.
3. Keep the node only if `node_identity_prop(field)` equals `value`
   (stored-wins).
4. **Also** include any node whose **stored** `field` equals `value` and whose
   key is different (the stored-wins hit that `ScanKey` would miss). Use the
   existing property index if that field is indexed; otherwise a label/property
   filter. Union, dedupe.

`n.label` / `labels(n)` are **not** this fold (not a key).

Pin:

- `where_n_id_eq_literal_uses_scan_key` — `insert_node` without stored `id`;
  `SCAN_KEY_FIRES` (or the identity-eq counter) increments; result is the node.
- `where_n_id_respects_stored_wins` — the §5.1 stored-prop fixture still holds
  under the fold.
- `where_n_key_eq_param_uses_scan_key` — `$k` form.

### 5.3 Write `RETURN` parity

`eval_set_return_operand` (`crates/core-api/src/db.rs`) currently errors on
`Operand::Case` and `Operand::Index`. The read path already evaluates both.

Wire CASE and list subscript through the same evaluator the read path uses
(or a thin adapter that has `GraphDb` + the MATCH row). Identity fallback
must apply on `Operand::Prop` (`n.key` / `n.label` / `n.id`), not only
`get_prop`.

Pin (launch-checklist #5 plus the subscript twin):

- `write_return_case_agrees_with_read` —
  `MATCH (n:Person) SET n.age = 30 RETURN CASE WHEN n.age >= 65 THEN 'senior' ELSE 'other' END`
  returns a row; a follow-up read of the same CASE matches.
- `write_return_list_subscript_agrees_with_read` — `SET` then `RETURN n.tags[0]`.
- `write_return_n_id_after_create` — `CREATE (n:Person {id: 'alice'}) RETURN n.id, id(n), n.key`.

Update `docs/site/query.md` coverage: remove the named-error rows for CASE and
subscript in write `RETURN`, or move them to Supported.

### 5.4 Python `upsert_node` and `query_at`

`GraphDb::set_props` already all-or-nothing. Python `upsert_node` update path
builds the changed `(field, value)` list and calls `set_props` once (skip
unchanged, same as today). Create path stays `insert_node`.

`query_at` gains optional `role: Option<&str>` and `namespace: Option<&str>`
and calls `query_at_scoped` with the same `AsOfScope` live `query` uses.
Invalid role → the same error live `query` raises.

Pin:

- `test_upsert_node_update_is_one_commit` — two fields change; `commit_seq`
  advances by 1; a mid-list refusal (reserved / `ns` change) leaves both
  fields untouched.
- `test_query_at_role_and_namespace` — a role-scoped as-of read agrees with
  `query(..., role=)` at that commit.

### 5.5 Kernel speed (no graph-shape)

All three are allocation / redundant-normalise. Dist-eval counts and neighbour
sets must not change.

1. **`beam_search` scratch.** Today each search allocates `visited: Vec<bool>`
   and the candidate heaps (`hnsw.rs`). Thread-local (or `&mut Scratch` on
   `HnswIndex`) reuse, cleared per call. Determinism preserved.
2. **Query `f32` buffer.** `search` converting `q: &[f64]` via `as_f32` per
   call allocates. Reuse a side buffer on the index or scratch.
3. **GEMM `pack`.** If the input is already unit length (within the same
   epsilon the packer uses), do not L2 twice (`exact_knn.rs`). Scores stay
   within the existing GEMM-vs-scalar pin.

Pin:

- `beam_search_scratch_does_not_change_hits` — same `k` hits and order as
  before on a fixed seed (or equal `hnsw_dist_evals` on a fixed insert+query).
- `pack_skips_second_l2_on_unit` — unit vector in, packed row equal to the
  current pack (within ulp).
- Recall gates unedited still pass.

Do **not** change `HnswParams` defaults.

### 5.6 HTTP neighborhood 404

`GraphError::KeyNotFound` through `key_not_found`, not `graph_err`. Body
string stays `node key not found: {key}` (`GraphError::KeyNotFound` Display,
already pinned in `doc_strings.rs`).

Fix `docs/site/api.md` if it still shows `"key not found: …"` without `node`.

Pin: `neighborhood_unknown_key_is_404` in the HTTP test crate.

### 5.7 HTTP `POST /find_similar`

New route, **not** under `/algo/*` (those deny role tokens). Body JSON:

```
field, vector, k?, min?, label?, mask?, where?, exact?
```

Semantics = Python `find_similar` at 0.6.8: `where` is `PropPredicate`
(`eq` / `in`); `where` or `exact=true` skip HNSW; `mask` alone is the 0.6.7
widening beam; role token **intersects** the mask. Default `min` on HTTP
matches Python (**0.0**), not MCP (**0.8**) — document both.

Unknown key in an explicit mask: skip (existing mask behaviour). Invalid
`where` → 400 `QueryError`.

Pin: `http_find_similar_exact_agrees_with_python_shape` (JSON hits =
`GraphDb::find_similar` on the same store); `http_find_similar_role_intersects_mask`.

### 5.9 Degree insert-count (no CSR multi-edges)

Topology stays a set. `add_edge` still returns false on a duplicate pair.
Unresolved NULL targets still do not exist as edges.

**Persistence without V9:** a reserved **edge property** `count` (integer ≥ 1).
Absent means 1. A duplicate `insert_edge` / user-edge CREATE that would no-op
instead `set_edge_prop(..., "count", n+1)` using the existing edge-prop WAL
(no new `WalRecord` variant, so a 0.6.8 reader that never wrote counts still
opens; a 0.6.8 reader that meets counts just ignores a property it does not
sum).

`delete_edge` still removes the unique pair **and** its properties (all
insert-count gone). One delete, not N decrements.

API:

- Rust `degree` / `degrees` gain `multiplicity: bool` (default **false** =
  unique, today’s number).
- Python `degree(..., multiplicity=False)` / `degrees(..., multiplicity=False)`.
- HTTP: no new centrality route. Optional query/body flag only if a
  per-node degree HTTP already exists; otherwise Python/Rust is enough for
  this patch. Do **not** change `POST /algo/degree` (that is centrality).

`count` as an edge property is **reserved**: user `SET` on it is refused the
same way view-owned node props are, or it is namespaced as a non-Cypher
field the executor never projects. Pick one and pin it. Do not let a Cypher
`SET` clobber insert-count.

Pin:

- `duplicate_insert_increments_count_not_unique_degree` — second `insert_edge`
  returns false; unique `degree` unchanged; `degree(..., multiplicity=true)`
  is 2.
- `delete_edge_clears_multiplicity` — after delete, both readouts are 0 /
  `KeyNotFound` as today.
- `multiplicity_survives_reopen` — snapshot + open; multiplicity still 2.
- Existing `duplicate_edge_does_not_increase_degree` **stays green** (unique
  default).

Known limit that **remains:** NULL / unresolved targets never increment
anything. State that in CHANGELOG.

### 5.10 MCP `stats` roster

Today `tool_stats` loads `g.stats()` (full roster) and `retain`s only when
`role` or `namespace` is set.

Change: if **neither** `role` nor `namespace` is passed, **omit**
`namespaces` from the JSON (or emit `[]` — pick **omit**, so a client that
should not learn names does not see a key full of them). Store-wide
`nodes` / `edges` / `rules` / `history_floor` unchanged.

With `role` and/or `namespace`: current retain behaviour (visible names
only).

HTTP `GET /stats` for a role token stays closed (0.6.7 known limit already
points operators there). Do not open it in this patch.

Pin: `mcp_stats_unscoped_omits_namespace_roster` — two namespaces in the
store; unscoped `stats` JSON has no `namespaces` key (or empty); scoped
`stats` with `namespace` shows that one name.

This **is** a behaviour change for an agent that discovered tenants via
unscoped MCP `stats`. Document it under CHANGELOG `#### Changed`.

### 5.11 MHNS v4 — persist parked and refusals

`HNSW_BLOB_VERSION` **3 → 4**. Snapshot section 6 stays opaque; **V9
unchanged**.

Persist on the index (v4 body):

- `dim_mismatches: u64`
- refused node ids (the set `can_answer` needs so a mixed-dim corpus does
  not look complete)
- `parked: Vec<(u32, vector)>` in the **current** slab unit (`f32` rows),
  not a second `f64` copy

Decode:

- v3 (and v1/v2 as today) → parked empty, mismatches 0, then **today’s
  open-time re-offer** fills them.
- v4 → restore; open-time re-offer **skips** ids already refused or parked
  in the blob.
- v5+ → existing “future version” path: do not decode; `hnsw_tracked` full
  scan; never wrong.

A 0.6.8 binary meeting v4 fails the version check and scans. That is the
same contract v3 already has versus older readers.

Pin:

- `a_refused_vector_is_still_refused_after_a_reopen` — already exists;
  **add** that a v4 blob’s `dim_mismatches` after open equals before, and
  the open-time insert counter for that id is 0 (not re-offered).
- `a_parked_vector_survives_a_reopen` — same for parked.
- `v3_blob_still_loads_and_reoffers` — compat.

## 7. Key decisions

1. **HNSW growth is out.** Dist-eval cuts change the graph. This patch does
   not touch `HnswParams` defaults.
2. **Listing grows to 16.** Owner 2026-09-17: add `pairwise_similar` to the
   advertised association surface. Insert after `find_similar`. Handshake and
   listing tests move with it.
3. **No V9, no CSR multi-edges.** Insert-count lives on the unique pair as an
   edge property. Default `degree` stays unique so 0.6.8 tests stay green.
4. **MHNS v4, not snapshot v10.** Parked/refusals are index state; the
   opaque blob already versions independently.
5. **Unscoped `stats` omits names rather than inventing MCP auth.** HTTP
   role-token `/stats` stays closed.
6. **HTTP `find_similar` is a first-class read, not `/algo/*`.** Role tokens
   must be able to call it under the intersect-mask rule.
