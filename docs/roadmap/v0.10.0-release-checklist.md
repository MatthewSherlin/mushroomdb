# v0.10.0 — the steps only a person takes

Prepared on 2026-10-28 on `v0.10/completion`. The branch starts at `release/0.10`
(`aa230363`) and adds TY-15, PF-06b, PS-5, ALG-CF, the ignored-test allowlist
cleanup, rows 67 and 85, the invisible-character class, the upgrade guide, the
0.10.0 changelog section and this checklist. The version commit sets every
site to **0.10.0**. Nothing has been tagged or published.

## Before anything leaves this machine

A tag freezes each of these. Tick it to accept, or change it first.

- [ ] **D1 — V11 is opt-in.** A store that never stores a new value type, a
      unique constraint, a range index or a relationship property stays
      readable by 0.9.x. The first such write moves it to V11, at a one-time
      snapshot cost (5.6 s at 1M nodes in the spec). 0.9.x refuses a V11 store
      with `snapshot: unsupported version 11`.
- [ ] **D2 — Python memory methods are deprecated, not removed.** `db.remember`
      and the other five still work and emit `DeprecationWarning`. Removal is
      0.11. See `docs/site/upgrade-from-0.9.md`.
- [ ] **D3 — Rust exhaustiveness.** `Value` and `GraphError` each gained
      variants. `json_to_value` returns `Result`.
- [ ] **D4 — row 90 is not fully closed.** Algorithm configs and the TypeScript
      overloads are fixed (ALG-CF). The invisible-character class includes C1,
      U+00AD, U+2060 and U+FE0F. A batch can still refuse a delete that two
      separate commits would allow, because the retraction is not visible
      inside the batch.
- [ ] **D5 — still deferred, now to 0.11:** rows 90 (in-batch retraction),
      101, 120, 121, 122, 136, 137, 140, 142, 152, 155, 156, 159. Row 121
      (a reload can mix two snapshots under the newer identity) is an engine
      follow-up, not fixed on this branch. The ledger names 0.11 so a 0.10.0
      workspace does not treat them as already shipped.
- [ ] **D6 — the concurrency gate is not green.** On PR 116's run
      (`40594950601`, job `122529058059`, 2026-10-27) a plain commit with no
      readers cost 1.34× v0.9.2 on that machine; the bound is 1.15×. The same
      commit under readers was 0.99× (bound 1.25×), and the reader latency gate
      passed. The docs in that PR do not touch the write path. This is the
      `release/0.10` writer cost, measured twice in that job. It is not
      re-run here.

## The tag — nothing after this can be taken back

- [ ] `git ls-remote --tags origin 'v0.10.0'` prints nothing.
- [ ] `git tag -a v0.10.0 -m v0.10.0 <the merge commit on main>` and
      `git push origin v0.10.0`.

|---|---|---|
| Six binaries, `SHA256SUMS`, the Homebrew formula | the GitHub Release | Deletable — but the npm launcher and the formula download from it |
| `:latest` and `:v0.10.0` | `ghcr.io/matthewsherlin/mushroomdb` | Overwritable; images already pulled are out |
| The crates, in dependency order | crates.io | **Never.** Yank only |
| Three abi3 wheels | PyPI | **Never** for that version |
| `mushroomdb` and `mushroomdb-client` | npm | The number is burned once used |
| `langchain-mushroomdb` and `llama-index-graph-stores-mushroomdb` | PyPI | **Never** for that version |
