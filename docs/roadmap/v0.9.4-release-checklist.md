# v0.9.4 — the steps only a person takes

Prepared on 2026-10-23. 0.9.4 carries four fixes, ledger rows 154, 157, 158 and 160, backported
from 0.10 onto `main` (v0.9.3, `5e0aff49`). It arrives in one pull request with six commits: one
per row, the ledger rows, and the commit that sets every version site to 0.9.4. Nothing has been
tagged or published.

**What the green does and does not prove.** Every local result is from one macOS machine: the
workspace suite ran with the child-process kill tests skipped (`crash_before_commit`, `killed`,
`abort`, `crash`, `ingest_git`), which hang on that host; CI runs them. Each row's tests fail on
`5e0aff49` and pass with its fix (the report, `.superpowers/sdd/_shared/v094-report.md`, has the
red and green runs). Not run by anyone: the test suite on Windows. No independent review of the
backport has run yet.

## Before anything leaves this machine

A tag freezes each of these. Each is in force on the branch; tick it to accept, or change it first.

- [ ] **D1 — this is 0.9.4, a patch release, and it carries rows 154, 157, 158 and 160 only.**
      Nothing else from `release/0.10`. No format version change: no byte layout in the snapshot
      or the WAL changed, so 0.9.3 opens a 0.9.4 store and 0.9.4 opens a 0.9.3 one.
- [ ] **D2 — row 158 changes a result type in a patch release** (owner's decision, 2026-10-23):
      `sum` of integers is now an `Int`, not a `Float`, and an integer overflow is the error
      `sum(): integer overflow`. The changelog names it under Fixed with the type change spelled
      out. `avg` is unchanged.
- [ ] **D3 — row 157 is the smallest fix that makes the null right.** 0.10's other QL-AG changes
      stay out of 0.9.4: `min` / `max` still read numbers (and booleans, row 160) only, so over
      strings they still return null; `sum(n)` / `min(n)` of a node variable is still null, not
      0.10's "expected a value, got a graph element" error.
- [ ] **D4 — row 160 is the ordering fix only.** None of QL-VE's compile-time checks, no `plan:`
      relabelling. 0.9.x has no range index, so `OrderClass::Bool` has no counterpart here.
- [ ] **D5 — row 154 is the edge-property merge only.** `EdgeProps::set` keeps a tombstone, the
      view reads the overlay entry before the tombstone, and the snapshot merge lays an
      untombstoned overlay entry over the archived one field by field. No relationship-property
      writes, no V11 records 28/29.
- [ ] **D6 — deferred to 0.10:** rows 44, 51, 54, 62, 63, 64, 65, 66, 67, 69, 70, 85, 88, 90, 101,
      102, 114 (seventeen, unchanged from 0.9.3).
- [ ] **D7 — merging `main` into `release/0.10` will conflict** on the ledger (rows 154, 157, 158,
      160 exist there with "CLOSED in 0.10"; take 0.10's text and set the status to "CLOSED in
      0.9.4 and 0.10"), on `exec.rs`'s `update_acc` (take 0.10's), `edge_props.rs`, `seam.rs`,
      `encode.rs` and `filter.rs` (take 0.10's), and on the version sites and CHANGELOG. The 0.9.4
      tests live in files 0.10 does not have (`aggregate_variables.rs`, and additions to
      `cypher_booleans.rs` and `snapshot_rules.rs`); they pin nothing 0.10 changes, so they
      should pass there.
