# v0.6.6 — the scale release: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop building a vector index twice, stop rebuilding it on every open, stop paying a
whole-index scan for a changed embedding, and stop holding the write lock for minutes while
`create_rule` backfills. Make an exact `VectorSimilar` rule find its candidates through that index
instead of comparing every pair. Add namespaces as a third visibility axis that composes with roles
and predicate masks, with an existing store as one implicit default namespace. Ship 0.6.6.

**Architecture:** Three items across three crates plus the server, the CLI and the Python binding.
**No format change.** The HNSW index already lives in the V9 snapshot as two opaque `Vec<u8>` per
rule (`crates/core-storage/src/v8/layout.rs:166-183`), so only the bytes inside it change and the
blob carries its own magic and version; a namespace is an ordinary node property, an appended
`RuleDef` field under the repository's existing positional-bincode ruling, and a `roles.json`
version bump. V9 stays V9 and `format-compat` is untouched. Two behaviour changes:
`create_rule` on a large corpus returns before its edges exist, and an exact `VectorSimilar` rule's
candidate set becomes approximate with a committed recall floor while its scores stay exact. One new
refusal (`SET n.ns`), one more (`insert_edge` across a namespace). No tool is added or removed and
no MCP listing moves: `ASSOCIATION_TOOLS` stays exactly the same fifteen in the same order and
`CODE_GRAPH_TOOLS` the same three.

**Tech Stack:** Rust 1.92 workspace (`crates/core-rules`, `crates/core-api`, `crates/core-storage`,
`crates/server`, `crates/cli`, `crates/sim-harness`), PyO3 (`bindings/python`), Markdown,
GitHub Actions.

**Spec:** `docs/roadmap/v0.6.6-scale-spec.md`.

**Branch:** cut from `feat/v0.6.5-knowledge-base`. Tasks 1–4 may run in a worktree while 0.6.5's
Tasks 5–8 finish; Tasks 5–7 require 0.6.5 merged (see **Ordering hazards**).

## Global Constraints

- **No commit trailers of any kind.** Commit with `git -c commit.gpgsign=false commit -m "<subject>"`.
- **`git add <explicit paths>` only.** Never `git add -A`, never `git add .`, never `commit -a`.
  Name every file you intend to commit.
- **Nothing committed names or compares against another database, graph or vector product.** The
  relational baseline is "the relational baseline" or "arm Q"; an external vector service is "an
  external vector index". Existing benchmark files that already name one are not edited.
- **Debug builds only** unless a task says otherwise. The three release runs this plan permits are
  named in Task 3 Step 6, Task 4 Step 6 and Task 7 Step 4; never trigger another.
- **TDD: the failing test comes first.** Every task writes its test, runs it, watches it fail for
  the stated reason, and only then implements.
- **Each task ends with its tests passing** — the exact command is named in the task's final step.
- Ships as **0.6.6**.
- **Every number in a product-facing document comes from a committed measurement in this
  repository.** Product-facing means `README.md`, `docs/site/**`, `llms.txt`, `llms-full.txt` and
  `CHANGELOG.md`. The deployment figures in the spec's §2 are a report from outside this repository
