# Query Language and Conformance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the Cypher parser, AST, planner, and executor so that real-world openCypher 9 queries run against mushroomdb 0.10 without modification, verified by a published TCK conformance score ≥ 65 %.
**Architecture:** All changes live in `crates/core-query` (parse/plan/exec) and `crates/core-api` (write-statement dispatch in `db.rs`); the TCK harness is a new non-published crate `crates/tck-runner` reading vendored `.feature` files; a new `ProcedureRegistry` trait in `core-query` is the only interface W3 must satisfy. No storage-format changes; `RemoveProp` and `SetProp` are the only WAL record types emitted by new write paths.
**Tech Stack:** `mushroomdb-query` (crates/core-query), `mushroomdb` (crates/core-api), `tck-runner` (new crate), `gherkin` crate (test-only), `rand` crate (approved per spec §9.1).
**Spec:** `docs/roadmap/v0.10-spec.md` and `docs/roadmap/v0.10/W1-query-language.md`

## Review Focus

The five failure modes most likely to escape a task's own tests:

1. **Null propagation in new scalar functions** — a function given a non-matching type (e.g. `trim(42)`) must return null, not an error. Several branches in `eval_func` propagate only the null case and fall through to an error arm; the type-mismatch → null rule is easy to miss for a subset of the 30+ new functions. Each task's test suite must include an explicit `assert_eq!(eval("trim(42)"), null)` case for every new function (pinned test added to Tasks 2–5, 12).
2. **Mask enforcement on named-path materialisation** — `nodes(p)` iterates constituent node ids and returns them as string keys. If any constituent node is hidden by `view.mask`, the entire path row must be suppressed (not just that node's key omitted). The mask check at materialisation time is separate from the mask already applied inside `VarExpand`/`ShortestPath`; an implementation that only masks the scan will expose hidden node ids through path functions. Pinned test added to Task 7.
3. **`SET n = map` replace form must emit `RemoveProp` for every unlisted prop AND fire the rules hook for each removal** — it is easy to implement `SET n = map` by only setting the new keys, leaving unlisted props intact. The rules engine fires only when the storage-layer `remove_prop` path is called; a `SetProp`-only implementation silently skips rule retraction. Pinned test added to Task 14.
4. **MERGE-with-edge must not create a duplicate edge when both nodes and the edge already exist** — the match-first logic must check for an existing edge of the given type between the resolved endpoints before inserting. The prior single-node `MERGE` only checks nodes; copying its pattern without adding an edge-existence check yields silent duplication. Pinned test added to Task 15.
5. **`CALL ns.name(args)` vs `CALL { }` parse disambiguation** — `CALL` followed by `{` (subquery) must produce the exact "not supported" error; `CALL` followed by `ident.ident(` must produce a `ProcCallStmt`. Falling through on the `{` branch gives an opaque parse error instead of the specified message; falling through on the `ident.ident` branch rejects valid procedure calls. Pinned test added to Task 10.
