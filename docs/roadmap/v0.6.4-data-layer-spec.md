# v0.6.4 — the data-layer release: design

**Date:** 2026-09-11
**Status:** draft for owner review
**Owner decision it implements (2026-09-11):** the code-graph door is measured and does not pay.
0.6.4 repositions the product around what the engine is measurably for — rule-derived
relationships with explain, retraction, time travel and role visibility, served to agents over MCP
or embedded — and marks the code door deprecated: still working, still tested, off the front door,
removed in 0.7.

## 1. Goal

One release of positioning and honesty. **No engine change, no tool removed, no format change.**
When it ships:

1. `README.md` and `docs/site/index.md` lead with the entity data layer, not the repository graph.
2. Everything on the code door carries a deprecation notice a user actually sees: a docs banner, a
   line printed by `install`, a changelog subsection naming what 0.7 removes.
3. Every "faster coding" / "fewer tokens" claim is gone from the product surface, and a committed
   check keeps them gone.
4. The roadmap documents for the code door are closed, each with a closing note saying what it
   proved.
5. Tool counts do not move: 27 served, 15 listed on an entity store, 3 on a store built by
   `ingest-git`. A patch release does not break an existing install.

There is no benchmark gate in this release. Nothing measurable changes; the measurements already
exist and this release reports them where a reader will meet them.

## 2. What we learned

All figures below come from committed summaries in `benchmarks/agent-tasks/results/`. No number in
0.6.4's docs may come from anywhere else.

**The code door, 240 cells** ([`20260910T000418Z`](../../benchmarks/agent-tasks/results/20260910T000418Z/summary.md),
arms A stock / B installed / C invoked / D cli × 3 reps × 20 tasks, two repositories):

| | A stock | B installed | C invoked | D cli |
|---|---|---|---|---|
| score | 0.927 | 0.941 | 0.924 | 0.920 |
| cost $ | 0.2267 | 0.2396 | 0.2713 | 0.2290 |
| adoption | 0% | **0%** | 43% | **0%** |

Paired against stock: C score `-0.0035 [-0.0112, 0.0017]`, cost `+0.04463 [+0.01312, +0.07471]` —
**no correctness gain and about +20% cost when the graph was used**, and **0 graph calls in 120
unprompted sessions** (arms B and D, 60 cells each). The gate failed on every arm.

**The association suite, 180 cells** ([`20260911T005749Z`](../../benchmarks/agent-tasks/results/20260911T005749Z/summary.md)
before the 0.6.3 fixes, [`20260911T065400Z`](../../benchmarks/agent-tasks/results/20260911T065400Z/summary.md)
after; arms P files+grep / Q the relational baseline / R the store × 3 reps × 20 tasks):

| | P files + grep | Q relational | R graph (before) | R graph (after) |
|---|---|---|---|---|
| score | 1.000 | 0.974 | 0.795 | 0.967 |
| cost $ | 0.0949 | 0.1158 | 0.5089 | 0.0923 |
| turns | 6.90 | 7.38 | 25.55 | 5.07 |

The graph arm reached parity with the relational baseline on correctness at a lower mean cost, and
is still behind files + grep on a 2,000-entity world. The gate failed on the cost interval.

**What that adds up to.** A coding agent holding `grep` does not need a graph and does not choose
one. The engine's value is not "find code faster"; it is relationships that are *derived*, that
*retract* when they stop being true, that *explain themselves*, that can be read *as they were*,
and that answer *differently per caller*. That is served to an agent over MCP or embedded as a
library or sidecar — and a repository is one data source among several, not the product.

## 3. The repositioned front door

One paragraph of copy, drafted here and shipped as written (README under the tagline; the same
substance opens `docs/site/index.md`):

> mushroomdb is the data layer for agents that reason over entities. It is an embedded Rust graph
> database in which a relationship is a schema declaration: write a rule once, and every write
> derives, maintains and **retracts** the matching edges, each one carrying the rule, the score and
> the values that produced it. An agent reaches it over MCP — fifteen tools on an entity store — or
> you embed it as a Rust library, a Python module, or a sidecar beside your own service. Four
> questions are what it exists for: **why are these two related** (`explain_association`, answered
> with the evidence rather than an assertion), **what did that look like then** (`edges_at`, the
> edges a node had at any past commit), **what would this change do** (`what_if`, computed without
> writing anything), and **who may see it** (`query` with a `role`, so one graph answers differently
> per caller). Local-first: a directory on disk, no account, no endpoint, no LLM in the write path.

Immediately under it, a short notice pointing at the Deprecations section (§4), and the
`ingest-git` repositioning in one sentence: *`ingest-git` stays supported as a **data source** —
commits, pull requests, files and authors become entities with rule-derived relationships, which is
what makes a ticket↔commit predicate a rule rather than a script.*

## 4. The deprecation policy

What **deprecated** means to a user in 0.6.4, stated once in README and repeated verbatim on each
deprecated page:

- It **still works** in this release. Nothing is removed, nothing is gated behind a flag it was not
  already behind, and the tests that covered it still run on every release.
- It is **no longer promoted**: not on the front door, not in the skill's task rules, not in the
  plugin's description.
- A **notice is printed or shown**: a banner at the top of its docs page, and a line from `install`
  for each of the three hook flags.
- It is **removed in 0.7**.
- The **migration is: nothing to do** — unless you relied on the specific thing named beside it.

| Deprecated | Relied on it? |
|---|---|
| `explore`, `map`, `context`, `impact`, `owners`, `why`, `sync` | Pin `mushroomdb@0.6.x`. Nothing on the entity surface replaces them — they answer from a repository graph, which 0.7 stops shipping tools for. `ingest-git` and `query` keep answering the same facts as Cypher. |
| `--intercept-grep`, `--impact-before-edit`, `--enrich-grep` | Re-run `install` without the flag; the hook is removed the way any other manifest entry is. Nothing replaces them. |
| The plugin's coding-assistant positioning | The plugin is not going away. Its description and skill now lead with entity memory; the code tools it could reach are the row above. |
| Code-suite benchmark runs | `run.py --suite code` still runs. No further runs are committed; the committed summaries stay as the record. |

## 7. Non-goals

- **Deleting anything.** No tool, flag, hook, command or test is removed in 0.6.4; removal is 0.7's
  plan and is not written here.
- **Any engine change.** No new tool, no predicate, no on-disk format change, no listing change.
- The sidecar work (the owner's private repository) and the CTL wrapper.
- New benchmark runs of any suite. 0.6.4 reports what is already committed.
- Rewriting `docs/site/code-graph.md`'s body. It gets a banner; its measured content stays as the
  record of what the door does.
- Renaming the `code-graph` CI job, the `mushroom-memory` default store directory, or the
  `/mushroom` skill.

## 8. Decisions taken on the owner's behalf (revisit if wrong)

1. **`benchmarks/agent-tasks/` has no README today** — the retirement note needs a home, so the plan
   creates `benchmarks/agent-tasks/README.md` (both suites, which one is retired, where the record
   lives) and repeats one line of it in `run.py`'s module docstring.
2. **`v0.6.3-association-spec.md` moves to `closed/` beside its plan.** The owner named the plan;
   splitting a spec from its plan across two directories would leave a dangling link. Both close.
3. **The claim scrub is a shell script in the `plugin-validate` CI job**, not a Rust test: the file
   set is documentation, the job already runs docs-shaped checks, and it needs no toolchain.
4. **The deprecation line is an `install` summary note**, through the existing `notes` vector — not
   stderr, not a `doctor` check. `disable`, `enable` and `doctor` need no change this release.
5. **The `ingest-git` cascade GIF stays in the README**, re-captioned as what it actually shows: one
   `SET` deriving and retracting rule edges inside a single write. It demonstrates the engine, not
   the code door.
6. **`explore` stays the default listing on an `ingest-git` store.** Deprecating the listing as well
   would break every existing code-graph install in a patch release; the listing is 0.7's problem.
7. **`packaging/plugin/README.md` is hand-edited** — `render-plugin.sh` explicitly skips it.
8. **Version 0.6.4, not 0.7.** Nothing is removed, so nothing is breaking.
